# Вкладка «Копии документов» и процедуры выбора документов

Контекст для задачи по функционалу (не входит в модель данных текущей задачи,
но определяет, откуда новые формы будут брать документы).

В старой системе вкладка «Копии документов» формы претензии показывает два
вида материалов:

1. **Документы Диадок** (электронный документооборот) — по ремонту;
2. **Фотографии** (сканы/фото дефекта) — из годовых архивных БД.

Автоматически должны прикрепляться ВСЕ документы по ТР-2 (требование из issue).

## 1. `dbo.pTHP_DiadocSelectDoc` — документы Диадок по ремонту

```sql
exec pTHP_DiadocSelectDoc @IdZap int, @Vid_Rem tinyint, @Filters xml
-- пример из issue:
exec pTHP_DiadocSelectDoc 3393584, 4,
  '<f><p i="ВУ-23"><d i="ВУ-23"/></p>
       <p i="Рекламация"><d i="ВУ-41"/><d i="Прочее"/></p>
       <p i="ТР-2"><d i="РДВ"/><d i="ФПУ-26"/><d i="Справка 2612"/><d i="ВУ-36"/><d i="Счёт-фактура"/><d i="Прочее"/></p>
       <p i="Хранение з/ч"><d i="МХ-1Х"/><d i="МХ-1М"/><d i="МХ-3Х"/><d i="МХ-3М"/><d i="ФПУ-26"/><d i="Счёт-фактура"/><d i="Акт брак"/></p>
  </f>'
```

- **`@IdZap`** — идентификатор ремонта в `DRVagTR` или `DRVagRem` (НЕ ключ
  претензии! документы привязаны к ремонту, а не к претензии).
- **`@Vid_Rem`** — вид ремонта.
- **`@Filters`** — XML-фильтр по типам пакетов (`<p i="...">`) и документов
  (`<d i="...">`); задаёт и состав, и порядок.
- Источник: внешняя БД `arxthp` (архив пакетов): `PakVersion` (актуальная
  версия, `PakState = 3` — подписан; пакет ВУ-23 показывается даже
  неподписанный), `Pak`, `PakContent`, `PakDoc`, `PakDocDiaData`.
- Исключаются документы типов `Согласие`, `Отказ`.
- Возврат: `npp, PakTypeId, DocTypeId, MessageId, EntityId, EntityTypeId,
  DocFileName` (имя файла формируется как `[Пакет] ТипДокумента.pdf`).

**Типы пакетов:** ВУ-23, Рекламация, ТР-2, Хранение з/ч, Продажа з/ч,
Поставка с/ф, МХ-1.
**Типы документов:** ВУ-23, ВУ-41, РДВ, ФПУ-26, Справка 2612, ВУ-36,
Счёт-фактура, МХ-1Х, МХ-1М, МХ-3Х, МХ-3М, Акт брак, Прочее, Согласие, Отказ.

## 2. `dbo.pTHP_GrafDocCopySelect` / `dbo.pTHP_GrafPDFPreSelect` — фотографии

```sql
exec pTHP_GrafDocCopySelect @ndoc varchar(50), @datedoc smalldatetime, @Foto tinyint = 1, @Id int = null
exec pTHP_GrafPDFPreSelect  @ndoc varchar(50), @datedoc smalldatetime, @Foto tinyint = 1, @Id int = null
-- примеры из issue:
exec pTHP_GrafDocCopySelect '63163745', '20260616 12:31:00', 4, 667295
exec pTHP_GrafPDFPreSelect  '63163745', '20260616 12:31:00', 12, 667295
```

- Источник: годовые архивные БД **`ArxYYYY`** (год из `@datedoc`), таблица
  `VagPrivatIsklImg` (IdZap, Nom_Vag, Ord, img, Avtor, Date_Ins, ndoc, datedoc,
  Foto, nameImg, sizeImg).
- **`@Foto`** — тип фотографии: `1` (по умолчанию), `4`, `12` (PDF-превью).
- Режимы выбора:
  - `@Foto in (4, 12)` (в `GrafPDFPreSelect` — только `12`): выбор **по `Id`**;
    если `@Id` не передан, определяется как
    `select top 1 Id from TrkRemPretens where Nom_Vag = @ndoc and Dat_Rem = @datedoc`
    — т.е. строка претензии в старой системе идентифицируется парой
    **«вагон + дата ремонта»**;
  - иначе: выбор по `ndoc + datedoc + Foto`.
- `GrafPDFPreSelect` дополнительно возвращает `sizeImg` и ФИО автора
  (`kcmod.nvTRK_Login`).

## Значение для новой системы

- В новой системе документы Диадок и фото **не переносятся** в таблицы
  `dr_warranty_repair*` — они остаются во внешних системах (Диадок/`arxthp`,
  архив `ArxYYYY`). Модель данных текущей задачи их не содержит.
- Для вкладки «Копии документов» новой формы нужен сервис, который по
  **отцепке** (`wagnum + defect_date`/`repair_date`) собирает:
  - пакеты Диадок (аналог `pTHP_DiadocSelectDoc` — по ремонту/отцепке);
  - фотографии (аналог `pTHP_GrafDocCopySelect`/`pTHP_GrafPDFPreSelect` — по
    вагону + дате + типу).
- Привязка документов в старой системе — к **ремонту** (`IdZap` из
  `DRVagTR`/`DRVagRem`), а не к претензии. В новой системе ближайший ключ —
  `repair_uid` отцепки.
- Состав «автоматически прикреплённых документов по ТР-2» (пакеты ТР-2: РДВ,
  ФПУ-26, Справка 2612, ВУ-36, Счёт-фактура, Прочее + ВУ-23 + Рекламация +
  Хранение з/ч) — фиксирован, см. XML-фильтр выше.
