# Автоподписание: решение по статусу проверки и вкладка в окне результата

## Цель и границы

Работа 001 сделала решение об автоподписании (`AutoSignDecisionService`) и окно «Результат
проверки» на карточке пакета. Доработка:
- решение по проверке — по статусу строки `packet_check`: можно только при «Норме»;
- повторное согласование пакета, который уже во флоу, ничего не делает, и видно почему:
  автосогласован или отправлен вручную;
- автоподписание в окне — отдельная вкладка с таблицей проверок; это только информация;
- локальные данные, на которых видны разные варианты.

Не входит: колонка «Корректный пакет», `ok` в `/api/diadoc/processPacket`, АСУ ВРК,
`../rvk-diadoc`.

## Решения

- Автосогласование — короткий список проверок: настройка для типа → статус строки проверки =
  Норма (нарушение и предупреждение запрещают одинаково; в 001 запрещали только нарушения) →
  нет подписанных/отклонённых документов → пакет ещё не во флоу.
- Тексты нарушений в причину запрета не повторяются: они на вкладке «Проверки».
- Пакет во флоу, `approved_by` = «Автомат» (так пишет `/approve`, не «system») →
  «Автосогласован». Во флоу с другим пользователем → «Отправлен вручную на согласование».
- Не настроено / отключено — серый статус без таблицы.
- Данные для показа — синтетика в локальной БД.

## Что сделать

1. `AutoSignDecisionService`: причина `CHECK_NOT_NORM` по статусу пересчитанной строки вместо
   `CHECK_VIOLATION`; вместо `PACKET_APPROVAL_UNAVAILABLE` — `ALREADY_AUTO_APPROVED` /
   `SENT_MANUALLY` по `PacketFlow.approvedBy`; константа «Автомат» общая с `PacketSigningService`.
2. `PacketCheckDisplayService`: модель вкладки — состояние (автосогласован, отправлен вручную, не
   настроено, отключено, можно, нельзя) и строки проверок «Проверка | Результат | Подробности».
3. `DiadocPacketDetailView`: окно с вкладками «Проверки» и «Автоподписание».
4. i18n в `messages_ru.properties`.
5. Тесты: `AutoSignDecisionIT`, `PacketCheckDisplayServiceIT`, поправки ожиданий в связанных.
6. Синтетические пакеты ВУ-23 / МХ-1 в локальной БД с вариантами.

## Как проверить

- Тесты затронутого кода, затем `./gradlew :app:test` один раз.
- Браузер: карточка каждого варианта, обе вкладки окна, без сырых `msg://` и ошибок.
