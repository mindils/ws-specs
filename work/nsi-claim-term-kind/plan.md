# НСИ сроков этапов: вид претензии текстом, строки «повр», «Дата окончания»

Состояние: active
Предыдущая работа: [legal-tech-claim-ui](../legal-tech-claim-ui/summary.md)
Дата согласования: 2026-09-15

## Цель и границы

Справочник норм сроков претензионных этапов (`nsi_claim_term_norm`, аналог
`dbo.nvPretSrok` ВагТК) уже реализован в T07 работы
`dr-warranty-repair-rename-ui` и используется расчётом сроков претензий по
технологическим неисправностям: семь строк вида `KodPret = 1`, экраны
`nsi_NsiClaimTermNorm.list` / `.detail`, меню «Справочники → Сроки претензий:
календарь и нормы», роль `nsi-claim-term-edit`, ревизии с публикацией и
пересчётом. Пользователь принёс скриншот этого же справочника из ВагТК
([new-nsi.md](../legal-tech-claim-ui/input/new-nsi.md), `img1.png`) и полную
выгрузку таблицы ([nvPretSrok_full.sql](input/nvPretSrok_full.sql)).

Расхождения экрана с ВагТК, которые закрывает эта работа:

1. «Причина отцепки» выводится числом `claimKind = 1`; нужен текст «техн» /
   «повр» с выбором из списка.
2. Девяти строк вида «повр» (`KodPret = 3`) в наполнении нет.
3. Нет колонки «Дата окончания» (`Finish`) — справочный текст, заполненный
   у двух строк «повр».
4. Подписи колонок отличаются от старого экрана.

Второй скриншот (`img2.png`: срок передачи, дата передачи, номер ПСР)
покрыт списком претензий закрытой работы и в объём не входит.

**Не входит:** раздел претензий по повреждениям вагонов и расчёт сроков по
строкам «повр» (расчёт по-прежнему берёт только нормы вида «техн»);
изменение алгоритма расчёта, порогов 1/10/30 и календаря; пороги и цвета в
НСИ не выносятся.

## Общие решения

| Решение | Основание |
|---|---|
| Работа новая, закрытая `legal-tech-claim-ui` не переоткрывается; её материалы читаются по ссылкам | Ответ пользователя 2026-09-15; протокол закрытых работ |
| Сид семи строк «техн» в `04-data/331` остаётся; девять строк «повр» добавляются отдельным changeSet того же файла с `ON CONFLICT (claim_kind, operation_code) DO NOTHING`. Повторный прогон не создаёт дублей и не затирает ручные правки | Ответ пользователя 2026-09-15 («заполнение будет вручную», сид оставить); выгрузка |
| Enum `ClaimKindEnum implements EnumClass<Integer>` в `ru.fgk.ws.app.nsi.entity`: `TECH(1)` — «техн», `DAMAGE(3)` — «повр». Колонка `claim_kind INT` и её значения не меняются; константа `NsiClaimTermNorm.CLAIM_KIND_WARRANTY` заменяется на `ClaimKindEnum.TECH` во всех потребителях | Техническое решение; образец `pt/entity/PtClaimType.java` |
| Новая колонка `finish_note VARCHAR(500)` (`Finish`, «Дата окончания») — справочный текст, как `start_note`; в расчёте не участвует. `createTable` обновляется и добавляется отдельный `addColumn` с preConditions | Правило проекта для новых полей; заполнена у двух строк «повр» |
| Подписи экрана по ВагТК: «Причина отцепки» (`claimKind`), «Наименование операции» (`name`), «Нормативный срок (дней)» (`termDays`), «Дата начала» (`startNote`), «Дата окончания» (`finishNote`); «Тип дней» и «Порядок этапа» остаются. В расчёте день считается по `dayType`, поэтому в подписи не пишется «раб.» | Косметика под скриншот; тип дней уже настраиваемый |
| Расчёт сроков (`ClaimTermCalculator`, `ClaimTermNormService.loadNorms`) продолжает читать только нормы `TECH`; строки `DAMAGE` — справочные данные до появления раздела повреждений | Раздела повреждений в Jmix нет |
| Ключи i18n entity и enum — в блоке `ru.fgk.ws.app.nsi.entity/*`, ключи экрана — `ru.fgk.ws.app.nsi.view.claimtermnorm/*` файла `messages_ru.properties`; чужие блоки не переставлять | Правило проекта |

## Критерии всей работы

- На пустой БД после миграций в `nsi_claim_term_norm` 16 строк: 7 с
  `claim_kind = 1`, 9 с `claim_kind = 3`; повторный прогон миграций и
  ручная правка нормы не создают дублей и не откатывают правку.
- Список и карточка нормы показывают вид претензии текстом «техн» / «повр»,
  поле выбирается из списка, подписи колонок соответствуют скриншоту,
  «Дата окончания» видна и редактируется.
- Расчёт сроков претензий не изменился: `TechClaimDeadlineIT`,
  `ClaimTermCalculatorTest` и `TechClaimDeadlineService.describe` дают
  прежние значения; строки «повр» на расчёт не влияют.
- Правка нормы по-прежнему открывает черновик ревизии, публикация
  пересчитывает сроки.
- Гейты: `./gradlew :app:compileJava`, `spotlessCheckAll`, `:app:test` с
  `0 failing`, render-проход экранов НСИ норм браузером под ролью
  `nsi-claim-term-edit`.

## Как выполнять

Работа из одного таска: `task-execute` на
[tasks/T01/task.md](tasks/T01/task.md), затем `task-verify`, затем
`task-close`. Окружение — как в закрытой работе: `docker info`,
`(cd docker && docker compose up -d)`,
`app/src/test/resources/application-test-local.properties` с
`jdbc:postgresql://localhost:5432/postgres?currentSchema=main`. Браузерная
проверка: `bootRun` в фоне, вход `user`/`user` через `/local-login`,
назначить роль `nsi-claim-term-edit` через администрирование.
