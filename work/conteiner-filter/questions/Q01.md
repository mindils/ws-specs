# Q01 — Перенос справочных фильтров внутрь rvkFilter после доработки аддона

Статус: resolved
Затронутые таски: [T02](../tasks/T02/task.md), [T03](../tasks/T03/task.md),
[T04](../tasks/T04/task.md), новый [T05](../tasks/T05/task.md)
Блокирует: нет — T01–T04 приняты; новый объём оформлен отдельным таском T05,
после которого T04 проходится повторно

## Вопрос и факты

План 2026-09-16 оставил 9 фильтров по справочникам `cnt_*` штатными
`propertyFilter` + `entityComboBox` над `rvkFilter`, потому что аддон не умел
ссылки на сущности, а остальные ссылки (собственник, исполнитель, договор,
неисправность и т. п.) вошли в `rvkFilter` текстовыми полями по пути
(`owner.shortname`, `org.shortname`, `contract.contractNum`…). 2026-09-17
пользователь сообщил, что аддон доработан: «теперь можно выбирать в том числе
и entity», и попросил перенести все вынесенные фильтры внутрь `rvkFilter`.

Проверено 2026-09-17:

- Рабочее дерево `../rvk-filter` (uncommitted) содержит типы `entity` и
  `entityList`, атрибуты `lookup`, `optionsLimit`, элемент `<flt:itemsQuery>`
  (`docs/xml-api.md` «Ссылки на сущности», `docs/examples/entity-view.xml`,
  `docs/compatibility.md`). Jar `rvk-filter/build/libs/rvk-filter-0.0.1-SNAPSHOT.jar`
  собран 2026-09-17 00:28, исходников новее jar-а нет. В `libs/` лежит jar
  0.0.1 от 2026-09-14 без этой поддержки (в его XSD нет `lookup`).
- Liquibase changelog аддона не менялся (те же `001`, `002`). Java API
  совместим: `FilterState.of(query, activeIds, values, presetId)` сохранён,
  добавлен пятиаргументный вариант с `disabledFieldIds`.
- Автотип ссылки — `entity` (EQUAL, NOT_EQUAL); `IN_LIST` даёт `entityList`.
  Условие строится по `<property>.<pkName>`; опции ищутся `contains` по
  строковым свойствам `@InstanceName` через constrained `DataManager`;
  `lookup="auto"` даёт кнопку «Выбрать…», если у сущности есть list view.
- Все `cnt_*` имеют строковый `@InstanceName` и `Long id`; `VOrgPassport` —
  `@DbView`, `@InstanceName shortname`, `Long id`, list view нет (кнопки
  выбора не будет, поиск по вводу работает); `ContainerContract` —
  `@InstanceName contractNum`, list view `cnt_ContainerContract.list` есть.
  `VStation` — вычисляемый `@InstanceName` (`stName` + `stCode`), поиск без
  своего `itemsQuery` невозможен.
- `container-read` уже даёт READ на `VOrgPassport`, `ContainerContract` и
  `cnt_*`. `jmix.eclipselink.use-inner-join-in-condition=true` в приложении:
  на EQUAL не влияет, отрицания по ссылке не используются.

Локально не решается объём (какие ссылки переносить) и режим выбора (одно
значение или несколько) — это видимое пользователю поведение.

## Варианты и рекомендация

Объём: (а) только 9 выпадающих списков — ровно то, что было вынесено, меньше
объём; (б) списки плюс все ссылки на `VOrgPassport`, `ContainerContract`,
`cnt_*`, стоящие текстом по пути, — единообразный выбор из справочника,
лишние ключи `filter.*` удаляются; станции `VStation` в любом варианте
остаются текстом. Режим: одно значение (`entity`, EQUAL — как прежние списки)
либо несколько (`entityList`, IN_LIST). Рекомендация автора: (а) и одно
значение.

## Ответ пользователя

2026-09-17, чат: объём — «Списки + ссылки на org/contract/cnt_*»; режим —
«Одно значение, как раньше».

## Ответ и основание

Внутрь `rvkFilter` переносятся 9 прежних выпадающих списков и все ссылки на
`VOrgPassport`, `ContainerContract` и `cnt_*`, которые стояли текстом по пути:
`owner`, `org` (ремонты, освидетельствования, договоры), `repContract`,
`contract` (акты, гарантии), `defect`, `defectReason`, `warrBegin`, `genChar`,
`CntDefect.defectReason`. Поля объявляются `flt:propertyFilter` без `type` и
`operation` (автотип `entity`, EQUAL, `lookup="auto"`). Ссылки на `VStation`
(`repSt`, `rejectSt`, `repStInstr`) и `container.contNum` на ремонтах и
освидетельствованиях остаются текстом. Штатных `propertyFilter`, панели
`filterPanel` и справочных `collection`/`loader` на списках раздела не
остаётся. Jar аддона в `libs/` обновляется до 0.0.2 из рабочего дерева.
Основание — ответ пользователя и факты выше. Последствия: результаты проверок
T02 (C1 в части выпадающих списков, тест пересечения со штатным фильтром) и
T04 (сквозной проход) устаревают; после T05 T04 проходится повторно.
