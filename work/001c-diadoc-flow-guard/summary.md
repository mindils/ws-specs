# Повторные вызовы NiFi: `/approve` и `/sign` сами проверяют флоу

## Что появилось

- **`/api/diadoc/approve`, пакет уже во флоу** (флоу есть и не «возвращён на доработку»):
  - сразу отказ, ответ по форме прежний: `AUTO_SIGN_BLOCKED`, одна причина
    `ALREADY_AUTO_APPROVED` («Пакет уже автосогласован …») или `SENT_MANUALLY` («Пакет отправлен на
    согласование вручную …»);
  - решение не пересчитывается, **в БД ничего не пишется**: в `packet_check` остаётся решение, по
    которому пакет согласовали. Раньше каждый повтор перезаписывал флаги Диадок, `status` и
    `auto_sign_*`.
- **`/api/diadoc/sign` подписывает только автосогласованный пакет, который ждёт подписания:**
  `approved_by` = «Автомат» и статус флоу `TO_SIGN`. Отказ ничего не пишет:
  - `NOT_AUTO_APPROVED` — флоу нет («Пакет не согласован автоматически») или согласовал человек
    («Пакет согласован вручную (<кто>): автоматически не подписывается»);
  - `NOT_READY_FOR_SIGNING` — «Пакет не ожидает подписания: <статус>»: подписывается, подписан,
    ошибка и т. п.
  - Раньше статус не проверялся: повторный `/sign` по пакету на подписании или подписанному
    переводил пакет и его неподписанные документы в ERROR (`prepareForSigning` →
    `markPacketAsError(NO_DOCUMENTS_TO_SIGN)`).
- **`ok` в запросе `/sign` больше не учитывается**, как и в `/approve`. Решение принято при
  автосогласовании: на повторном сообщении `processPacket` может вернуть `ok=false`, и
  автосогласованный пакет иначе не подписался бы.
- Настройка `Diadoc.AutoSign.*` проверяется как раньше, до флоу.

## Как пользоваться

NiFi может вызывать `/approve` и `/sign` на каждое сообщение: каждый эндпоинт сам решает, делать
ли что-то.

| Ситуация | `/approve` | `/sign` |
|---|---|---|
| Пакет не во флоу, проверки пройдены | согласует | — |
| Автосогласован, подписание не запускалось (`TO_SIGN`) | отказ, ничего не пишет | **подписывает** |
| Автосогласован, подписывается или подписан | отказ, ничего не пишет | отказ `NOT_READY_FOR_SIGNING` |
| Автосогласован, подписание упало (`ERROR`) | отказ | отказ; перезапуск вручную на карточке |
| Согласован вручную | отказ `SENT_MANUALLY` | отказ `NOT_AUTO_APPROVED` |
| Не согласован (нет флоу) | решает по проверкам | отказ `NOT_AUTO_APPROVED` |
| Возвращён на доработку | решает по проверкам заново | отказ до нового согласования |

## Как устроено

- `AutoSignDecisionService.checkApproveFlow(messageId)` — флоу-шаг `/approve` (`checkCanApprove` +
  `approvedBlocker`). Им же пользуется полное решение для вкладки «Автоподписание».
- `PacketApprovalService.approve` вызывает `checkApproveFlow` до `calculateAndStore`.
- `PacketSigningService.checkSignFlow` читает `PacketFlow` через `UnconstrainedDataManager` и
  вызывается перед `startSigning`. Проверка `ok` удалена.
- `SignPacketErrorType`: новые `NOT_AUTO_APPROVED` и `NOT_READY_FOR_SIGNING`; `OK_STATUS_IS_FALSE`
  больше не выдаётся.

## Как проверено

- `AutoSignDecisionIT` (20):
  - после автосогласования появился флаг Диадок;
  - повторный `/approve` отвечает `ALREADY_AUTO_APPROVED`, флоу документов прежний;
  - строка `packet_check` (`status`, позиции, `auto_sign_*`) не изменилась.
- Новый `PacketSigningIT` (5), запуск подписания подменён:
  - `TO_SIGN` + «Автомат» с `ok=false` в запросе → подписание запускается;
  - нет флоу и согласован вручную → `NOT_AUTO_APPROVED`;
  - `PENDING_SIGN` / `FULLY_SIGNED` / `ERROR` → `NOT_READY_FOR_SIGNING`, статус флоу не меняется;
  - настройка выключена → `AUTOMATIC_SIGNING_DISABLED`;
  - во всех отказах подписание не вызывается.
- `PacketFlowRestControllerTest` (2) и `PacketCheckDisplayServiceIT` (9) — зелёные.
- Весь набор `./gradlew :app:test`: 2014 тестов, 0 падений, 12 пропущено.
- **Вживую на демо-пакетах не проверено.** На 8080 и 8081 работают ваши rvk-ws и rvk-diadoc,
  второй экземпляр rvk-ws не стартует (занят файл HSQLDB `vagtkprod.lck`). Слать `/approve` и
  `/sign` на ваш 8080 нельзя: там код без этой правки, а rvk-diadoc запущен — пошло бы настоящее
  подписание.

## Решено без вас

- Настройка `Diadoc.AutoSign.*` проверяется раньше флоу: выключенное автоподписание отвечает
  прежним `AUTOMATIC_SIGNING_DISABLED`.
- Тексты отказов `/sign` — русские строки в сервисе, как соседние сообщения этого ответа.

## Как шла работа

Одна сессия, ходов ritm нет, около получаса.

## Не сделано и ограничения

- Гонка двух одновременных `/approve` по новому пакету не закрыта: оба пройдут проверку флоу до
  записи. Нужна блокировка по messageId (например, `pg_advisory_xact_lock`), если NiFi может
  слать параллельно.
- Ручной запуск подписания с карточки (`DiadocDocumentFlowService.startSigning(UUID)`) в этой
  работе не менялся.
