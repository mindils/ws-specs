# Q02 — Выгрузки из старой ЕРК для начальных данных

Статус: waiting_user
Затронутые таски: [T10](../tasks/T10/task.md)
Блокирует: да — T10 не может начаться без файлов; остальные таски не зависят
Этап до блокировки: T10 не начинался

## Вопрос и факты

Пользователь решил загрузить начальные данные 13 справочников, договоров и
гарантийных условий из старой БД ЕРК (PostgreSQL, схемы `"MDM_DATA"`,
`"MDM_SHARE"`). Агенту старая БД недоступна. Старые числовые ИД сохраняются
как новые `id` (решение 2026-09-14), поэтому в выгрузках нужны бизнес-ключи.
DDL таблицы `warranty_type` в материалах отсутствует.

## Варианты и рекомендация

Единственный путь — выгрузка пользователем по готовым SELECT ниже. До ответа
идут T01, T02, T09 и далее; T10 ждёт.

## Разбор архитектора

Записи нужны только действующие: `lastrec = 1 and recdateend > now()`. Для
view `MDM_SHARE` фильтр не нужен. Персональные данные (`user_name`) не
выгружать. Организации договоров сверяются по `org_id`/ОКПО с `VOrgPassport`
(`ws_store.ora_assb_org_passport_current`), ожидается совпадение `org_id`.

## Для ответа

Контекст: делаем контейнерный раздел в РВК; справочники, договоры и условия
гарантии решено загрузить из старой ЕРК, чтобы операторы работали по
инструкции сразу (виды ремонта, «Документ к ремонту», договоры ФГК-47-15 /
ФГК-79-9, условия 385331 / 786974 / 786975). Без выгрузок справочники будут
пустыми, и всё придётся заводить вручную.

### Что нужно сделать

Выполнить SELECT-ы в старой БД и сохранить каждый результат в CSV (UTF-8,
первая строка — заголовок, разделитель `;`, даты `YYYY-MM-DD`, булево
`true/false`) в `specs/work/conteiner/input/seed/<имя>.csv`:

```sql
-- cnt_repair_type.csv
select repair_type_id as id, repair_type_name
  from "MDM_DATA".cont_repair_type
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_survey_type.csv
select survey_type_id as id, survey_type_name
  from "MDM_DATA".cont_survey_type
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_file_type.csv
select file_type_id as id, file_type_name
  from "MDM_DATA".eri_file_type
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_defect_reason.csv
select defect_reason_id as id, defect_reason_name
  from "MDM_DATA".cont_defect_reason
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_defect.csv
select defect_id as id, defect_name, defect_reason as defect_reason_id
  from "MDM_DATA".cont_defect
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_act_type.csv
select act_type_id as id, act_type_name, incl_sign
  from "MDM_DATA".eri_act_type
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_contract_type.csv
select contract_type_id as id, contract_type_name
  from "MDM_DATA".eri_contract_type
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_general_characteristic.csv
select char_id as id, char_name, char_name_pf
  from "MDM_DATA".gen_char_cont
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_model.csv
select id_char as id, model, tenty, dugi, trosy, vent
  from "MDM_DATA".cont_model_char
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_property_type.csv
select prop_type_id as id, prop_type_name, prop_group_name,
       prop_subgroup_name, comment, prop_type_name_lat
  from "MDM_DATA".cont_prop_type
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_container_type.csv
select cont_type_id as id, code, type_name, detail, kind_id
  from "MDM_SHARE".v_cont_type_bige order by 1;

-- cnt_container_size.csv
select cont_size_id as id, code, height, heighttxt as height_txt,
       width_f, comments
  from "MDM_SHARE".v_cont_size_big order by 1;

-- cnt_warranty_type.csv (все колонки) и её структура
select * from "MDM_DATA".warranty_type
 where lastrec = 1 and recdateend > now() order by 1;
select column_name, data_type, character_maximum_length, is_nullable
  from information_schema.columns
 where table_schema = 'MDM_DATA' and table_name = 'warranty_type'
 order by ordinal_position;

-- cnt_contract.csv
select contract_id as id, contract_num, contract_type as contract_type_id,
       date_begin, date_end, date_sign, org_id
  from "MDM_DATA".eri_contract
 where lastrec = 1 and recdateend > now() order by 1;

-- cnt_warranty.csv
select cond_id as id, contract_id, warr_type as warr_type_id, warr_duration,
       warr_begin as warr_begin_id, ext_warr_duration, insp_in_days, penalty,
       cont_type as cont_type_id
  from "MDM_DATA".warranty_cond
 where lastrec = 1 and recdateend > now() order by 1;

-- contract_orgs.csv — сверка организаций договоров с НСИ РВК
select distinct c.org_id, o.shname, o.okpo, o.inn
  from "MDM_DATA".eri_contract c
  left join "MDM_DATA".v_org_passports o on o.org_id = c.org_id
 where c.lastrec = 1 and c.recdateend > now() order by 1;
```

Структуру `warranty_type` (второй запрос) записать текстом в раздел «Ответ
пользователя» или файлом `input/seed/warranty_type_ddl.txt`.

По данным будет решено: состав `cnt_warranty_type`, seed-changelog T10,
соответствие `org_id` договоров записям `VOrgPassport`.
