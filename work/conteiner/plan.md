## Цель и границы

Перенести в Jmix-приложение РВК функционал старой системы ЕРК (MDM) по
контейнерам. Сейчас в РВК контейнерного раздела нет вообще. Результат: раздел
меню «Контейнеры» с самостоятельными страницами «Реестр контейнеров»,
«Ремонты контейнеров», «Освидетельствования контейнеров», «Договоры»,
«Гарантийные условия», «Акты»; карточка контейнера с вкладками Описание,
Характеристики, Ремонты, Освидетельствования, Акты, Файлы, История; группа из
13 контейнерных справочников в разделе «Справочники»; три роли. Справочники,
договоры и условия гарантии заводятся из UI и сдаются пустыми.

Доработка 2026-09-16 (внешний вид, функциональность не меняется): карточка
контейнера — один tabSheet с «Описанием» первой вкладкой и неактивными
остальными вкладками у нового контейнера; форма ремонта — пять вкладок вместо
аккордеонов; просмотр документа только когда файл есть (без заглушек с
картинкой); кнопки форм всегда внизу; статика `/img/**` без 403; в
затронутых view нет `css=`-атрибутов и новых CSS-классов.

Не входит: перенос начальных данных справочников, договоров и гарантийных
условий из старой ЕРК — отдельная работа ([Q02](questions/Q02.md)); вкладки
«Операции» и «Накладные» (отложены до появления источника,
см. [Q01](questions/Q01.md)); собственная таблица истории с датами
начала/окончания (пользователь продумает отдельно; пока история — Jmix
EntityLog); миграция самих контейнеров, файлов и старой истории; импорт из
Excel; конструктор полей; «Ремонтные предприятия» как отдельный справочник
организаций; любые автоматические расчёты; копирование внешнего вида старой
системы.

## Общие решения

Ответы пользователя 2026-09-11/12 (сохраняются): две основные роли + роль НСИ;
организации, станции и дороги — существующие `VOrgPassport`, `VStation`,
`VRailway`, дополнительные организации не создаются; номер контейнера trim +
верхний регистр, уникален глобально (в т.ч. среди удалённых), без проверки ISO;
`next_survey_date` реестра не зависит от освидетельствований; никаких
автоматических расчётов; `width_f` — длина в футах из размера; `rep_by_warr` и
`warr_on_rep` — две ссылки на условия гарантии; один файл у ремонта,
освидетельствования и акта; поиск, фильтры, сортировка, пагинация, настройка
колонок, Excel-экспорт; `genericFilter` не используется.

Ответы пользователя 2026-09-14:

- Самостоятельные страницы: Реестр, Ремонты, Освидетельствования (операторы
  работают через списки, см. инструкцию). Файлы — только вкладка карточки.
  Справочники — отдельные list/detail плюс добавление из lookup-выбора.
  Договоры, гарантийные условия и акты также получают пункты меню (решение
  планировщика по старому меню; при возражении убрать пункты, формы остаются).
- История — вкладка на Jmix EntityLog (audit addon). Своя таблица снимков не
  делается; таблица истории с датами начала/окончания — отдельная будущая
  работа.
- Операции и накладные отложены до появления в `ws_store` контейнерной
  дислокации и накладных ([Q01](questions/Q01.md)).
- Начальные данные: перенос 13 справочников, договоров и гарантийных условий
  из старой БД вынесен в отдельную работу (ответ 2026-09-15,
  [Q02](questions/Q02.md)). Решение сохранять старые числовые ИД как `id`
  остаётся в силе для той работы; здесь раздел сдаётся с пустыми справочниками,
  которые заполняются из UI.
- Ключи: генерируемый `Long id` (IDENTITY) у всех таблиц; номер контейнера —
  обязательное уникальное поле; связи по id.
- Обязательность полей — только в UI (`required` в view), колонки в БД nullable
  как в старом DDL. По скриншотам обязательны: контейнер в дочерних формах,
  «Дата браковки» в ремонте, файл в форме файла.
- Удаление — soft delete (`@DeletedBy/@DeletedDate`); старые «Закрыть» и
  «Удалить» = одно действие «Удалить».

Технические решения (основание — код проекта, см. contracts.md):

- Feature-domain `container`: пакет `ru.fgk.ws.app.container`, таблицы `cnt_*`,
  entity `cnt_*`, view-id `cnt_<Entity>.list|detail`, changelog author `cnt`.
- Все `cnt_*` entity: `Long id` IDENTITY, `@Version`, аудит создания/изменения,
  soft delete, Lombok только `@Getter/@Setter`, `@InstanceName`, FK только как
  `@DdlGeneration(unmappedConstraints)`, индексы на все ссылки.
- Запрет удаления при ссылках — `@OnDeleteInverse(DeletePolicy.DENY)` на
  `@ManyToOne`; нормализация и уникальность номера — listener + уникальный
  индекс в БД; копирование — общая утилита `EntityCopySupport`.
- Lookup организаций/станций — `entityComboBox` с `itemsQuery`; справочные
  поля — `entityComboBox` + `entity_lookup` + `entity_clear`.
- Карточка: `tabSheet`, вкладка = фрагмент с `CONTAINER_REF`, загрузка по
  `:containerId`, дочерние формы — диалоги, вкладки нового контейнера недоступны
  до сохранения.
- Файлы — `FileRef`, `fileStorageUploadField`, просмотр `DisplayFile`, папка
  хранилища `rvk.storage-folders.cnt-file`. Экспорт — `async_excel_export`.
- EntityLog: `LoggedEntity(auto)` + все атрибуты для всех `cnt_*` через
  liquibase `04-data`; фрагмент «История записи» по `entity` и
  `entityRef.longEntityId`; `entityLog.view` в `other_menu`.

Решения пользователя 2026-09-16 (пересмотр UI, основание —
`input/ui-review-2026-09-16.md`):

- Карточка контейнера: «Описание» — первая вкладка `containerTabSheet`; у
  нового контейнера остальные вкладки видны, но `setEnabled(false)` до первого
  сохранения; аккордеон `details` и подсказка `tabsHint` убираются.
- Форма ремонта: пять вкладок «Ремонт», «Исполнитель и договор», «Документы и
  стоимость», «Уведомление завода», «Документ».
- Просмотр `DisplayFile` показывается только при наличии файла (в формах —
  после загрузки, во вкладке «Файлы» — при выборе строки с файлом);
  `displayNotFoundFile` в разделе не используется.
- 403 на `/img/**` чинится здесь: `permitAll` в `IframeSecurity`.
- CSS: в затронутых view никаких `css="..."`, новых `classNames` и custom
  properties — только штатные атрибуты размеров, стандартные `themeNames` и
  уже используемые классы `buttons-panel`, `text-secondary`.

## Критерии всей работы

- Раздел «Контейнеры» и группа справочников доступны из меню; семь вкладок
  карточки работают на реальных данных, без заглушек.
- На пустом реестре редактор создаёт контейнер, затем ремонт и
  освидетельствование с выбором этого контейнера; сценарии инструкции 1–6
  воспроизводятся без обращения к старой системе.
- Все бизнес-поля матрицы доступны в формах и списках; обязательность — как
  решено; никаких автоматических расчётов и изменения связанных записей.
- Освидетельствование из отдельного списка и из карточки — одна запись и одна
  форма; то же для ремонта.
- Справочники, договоры и условия гарантии заводятся из UI, и заведённое
  условие гарантии выбирается в форме ремонта по подписи с его ИД.
- История EntityLog фиксирует создание, изменение и удаление и видна во вкладке.
- Soft delete, запреты удаления при ссылках и уникальность номера действуют вне
  view-контроллеров; три роли проверены в UI и через `DataManager`.
- Статические проверки, `./gradlew :app:test` и браузерные сценарии пройдены.
- После пересмотра 2026-09-16: кнопки форм не перекрывают поля; у нового
  контейнера вкладки неактивны и включаются после «Сохранить»; форма ремонта
  на вкладках; без файла нет панели просмотра и битых картинок; иконки
  `/img/filetype/*` отдаются с кодом 200.
