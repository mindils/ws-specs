## Результат и контекст

Рабочая страница реестра с карточкой контейнера. Реализованы Описание, Характеристики, Файлы и История; подготовлены точки подключения остальных пяти вкладок для T04/T05/T07. Пустые ещё не реализованные вкладки не выдавать за готовые.

Реестр является вручную заполняемым справочником самих контейнеров, которого раньше в текущей РВК не было. Обязательна кнопка «Создать контейнер» и полноценная форма заполнения на основе новой `cnt_container`. Справочник типов/моделей — лишь связанная классификация. Пустой реестр должен позволять редактору создать первый контейнер без импорта и внешнего источника.

Вход: [контракты UI и модель](../../contracts.md), [реестр](../../input/img_2.png), [карточка](../../input/img_3.png), [форма файла](../../input/img_4.png), результаты T01/T02.

## Критерии приёмки

- C1: Реестр открывается из меню; все поля `cont` доступны; номер нормализуется и остаётся уникальным после soft delete.
- C2: Модель показывает четыре количества, размер — длину в футах, тип — название; смена lookup обновляет эти отображения, ручные поля не пересчитываются.
- C3: Сохранённый контейнер получает характеристики и файлы; повторное открытие показывает реально сохранённые данные. Нет сирот при отмене создания/дочернего диалога.
- C4: Изменение номера сохраняет связи. Копия требует новый номер и не содержит старых детей, файлов и истории.
- C5: Удаление при действующих характеристиках/файлах и других модельных связях блокируется; после снятия связей разрешено. История остаётся.
- C6: Загрузка/замена/скачивание работают; прежний файл доступен из истории после замены/удаления. Отмена не добавляет бизнес-запись или снимок.
- C7: Просмотр не позволяет менять данные, в том числе через прямой маршрут/скачивание чужого недоступного снимка. Поиск/экспорт учитывают фильтры и права.
- C8: T04/T05/T07 получают документированный рабочий способ подключения вкладок; в текущем экране нет неработающих действий/пунктов меню.
- C9: На изначально пустом реестре через «Создать контейнер» вручную вводятся номер и данные, выбираются общие НСИ; после сохранения контейнер доступен по номеру в lookup связанных записей. Действие доступно роли ввода основных данных, не требует роли НСИ и не создаёт вместо контейнера только его тип.
