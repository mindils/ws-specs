## Результат и контекст

Вкладки «Операции» и «Накладные» с ручным созданием, просмотром, редактированием, копированием и удалением. Операция принадлежит одному контейнеру. Накладная — общий документ с набором контейнеров. Источников ЭТРАН нет и для согласованного поведения не требуется.

Вход: [матрица операций/накладных](../../contracts.md#операции-и-накладные), [старые SELECT и подписи](../../input/issue.md), модель T01 и каркас карточки T03. Старые SELECT используются только для состава полей, не исполняются и не становятся миграциями внешних view.

## Реализация

- Применить skills detail/list для создаваемых lookup-списков, fragment, dialog-detail-flow, service, fetch-plan, resource-role, i18n и тестов/проверок.
- Операции: показать и редактировать весь набор матрицы — время операции/получения, вагон, название операции, НРП, гружёность, станции/дороги дислокации, назначения и отправления, груз/вес, номер накладной, отправитель/получатель, источник. Не добавлять автоматическое получение данных по номеру вагона или накладной.
- Для существующих организаций и станций использовать lookup; дороги отображать из станций. Текстовые наименования без согласованного справочника оставить текстовыми, не создавать новый НСИ грузов/операций/состояний.
- Накладные: форма шапки со всеми полями матрицы и редактируемым набором контейнеров; один документ виден у каждого связанного контейнера. При создании из карточки текущий контейнер включён. Позволить связать с карточкой уже существующую накладную через lookup, не заставлять создавать дубликат документа.
- Различать снятие связи текущего контейнера и удаление всего документа. При снятии связи другие карточки сохраняют документ; при удалении предупреждать об общем документе и показывать затрагиваемые контейнеры. Применять транзакционную реализацию T01.
- История накладной содержит полный состав контейнеров; сохранение одного изменения связей без изменения шапки даёт корректную версию. Не создавать промежуточные частичные снимки.
- Подключить обе вкладки по контракту T03, запросы по id с пагинацией; UI-actions корректно обновляют выборку после save/remove/unlink. Добавить поиск, фильтры, экспорт, сообщения, права и историю.

## Критерии приёмки

- C1: Обе вкладки позволяют вручную сохранить и повторно открыть все поля матрицы; приложение не обращается к MDM/ЭТРАН и не требует их схем.
- C2: Операция одного контейнера не попадает в другой. Данные сохраняются на сервере, а не только в UI-контейнере.
- C3: Накладная, связанная с A и B, отображается в обоих; редактирование шапки видно обоим; добавление существующей накладной не дублирует документ или пару связей.
- C4: Снятие связи A оставляет документ у B; история отражает оба состава. Удаление документа выполняется осознанно и атомарно, без удаления A/B.
- C5: Существующая действующая связь блокирует soft delete контейнера. После unlink/delete она больше не блокирует; историческая связь сохраняется в снимке.
- C6: Отмена изменения состава контейнеров не сохраняет частичные связи/историю; concurrent edit обнаруживается. Подписи старой истории не меняются при редактировании НСИ.
- C7: Права просмотра/ввода проверены, экспорт учитывает контекст контейнера и выбранные фильтры, без дублей от joins.

Экспортировать отфильтрованные строки с колонками станций/организаций. Для каждой вкладки проверить серверные ошибки и отсутствие error overlay.

Команды: `./gradlew :app:compileJava`, целевые тесты с фактическими именами в result.md, `./gradlew :app:test`; затем последовательный браузерный проход.
