## Результат и контекст

Отдельная страница «Освидетельствования контейнеров» и одноимённая вкладка карточки работают с одной сущностью и общей формой. Пользователь вручную задаёт вид, три календарные даты, исполнителя и файл акта.

Вход: [контракты](../../contracts.md), [форма](../../input/img_5.png), [lookup контейнера](../../input/img_6.png), рабочие entity/history/roles и интерфейс подключения вкладок T03.

## Реализация

- Применить skills list/detail, dialog-detail-flow, fetch-plan, resource-role, i18n, тестов/проверок; переиспользуемую вкладку создавать по skill fragment.
- Добавить вторую основную страницу в меню, список с поиском/фильтрами/экспортом, одну форму просмотра/создания/редактирования/копирования/soft delete.
- Поля: сгенерированный id для просмотра, обязательный контейнер, вид освидетельствования, начало/окончание/следующая дата (без времени), исполнитель из текущего НСИ организаций, один файл акта. Остальные nullable-поля следуют модели T01, без неописанных обязательных дат или автозаполнения.
- В общем списке контейнер выбирается lookup с поиском. Из карточки он предзаполнен и фиксирован. Смена контейнера при разрешённом редактировании из общего списка корректно меняет принадлежность и историю; открытая карточка обновляет свою выборку при следующей загрузке.
- Реализовать загрузку/замену/просмотр/скачивание акта по общим файловым механизмам; история сохраняет предыдущий FileRef. Не копировать бинарное вложение при копировании записи.
- Ни создание, ни изменение, ни удаление освидетельствования не обновляет `next_survey_date` контейнера. Начало/окончание/следующая дата независимы от старых технических периодов.
- После save в диалоге обновить вкладку; после cancel — никаких изменений. Подключить историю, policies просмотра/ввода и все сообщения.

## Критерии приёмки

- C1: Две точки входа используют одну запись и форму; созданная запись видна в общем списке и правильной карточке, без дублей.
- C2: Lookup находит контейнеры по номеру; даты остаются календарными после сохранения/повторного открытия; исполнитель выбирается из текущего НСИ.
- C3: Любая операция над освидетельствованием оставляет ручную следующую дату контейнера неизменной, включая удаление и перенос к другому контейнеру.
- C4: Файл акта скачивается/просматривается; замена не уничтожает прежний файл в истории.
- C5: Cancel не сохраняет изменения, копирование не переносит id/историю/вложение, soft delete даёт историческую версию и убирает запись из действующих списков.
- C6: Роль просмотра не записывает данные; роль ввода имеет необходимые атрибутные и view-права во всех точках входа. Фильтры и экспорт согласованы с отображаемым списком.
