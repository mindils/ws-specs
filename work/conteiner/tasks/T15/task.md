# T15 — Сквозная проверка после пересмотра UI

Статус: todo
План: [plan.md](../../plan.md)
Зависимости: [T11](../T11/task.md), [T12](../T12/task.md), [T13](../T13/task.md), [T14](../T14/task.md)

нет.

браузерный проход сценариев инструкции под ролями.
Актуальная проверка: нет

## Коротко

После четырёх параллельных UI-тасков собираем раздел вместе: полный прогон
тестов, форматирование, сквозной браузерный сценарий «контейнер → ремонт с
документом → освидетельствование → файл» и сверка, что в разделе не осталось
аккордеонов, `split`-ов с просмотром, `css=`-атрибутов и заглушек с
картинкой. Найденные дефекты исправляются здесь, контракты приводятся к
фактическому состоянию, после чего работа закрывается `task-close`.

## Результат и контекст

Итоги T11–T14 — в их `result.md` и отчётах `checks/`. Требования пользователя —
[ui-review-2026-09-16.md](../../input/ui-review-2026-09-16.md). Сценарии
операторов 1–2 — [instruction-erk.md](../../input/instruction-erk.md).
Прошлая сквозная проверка — [T08/checks/002.md](../T08/checks/002.md):
пользователи `user_read`, `user_edit`, `user_nsi`, известный фон падений
легаси-тестов (49 в 11 классах `dr`/`pt`/`mh`/`diadoc`).

## Область и изоляция

Правки дефектов — в любой области контейнерного раздела (`container/view/**`,
messages) и `contracts.md`; фиксировать в result.md, какие файлы затронуты.
Общие ресурсы: всё (БД, порт, браузер, gradle daemon, MinIO). Выполняется
последним, параллельных тасков нет.

## Реализация

1. Убедиться, что T11–T14 в `done`, прочитать их result.md и checks.
2. Слить изменения в один worktree/ветку, `./gradlew spotlessApply`.
3. Механическая сверка по `app/src/main/resources/ru/fgk/ws/app/container`:
   `grep -rn 'css=\|<details\|<split' --include=*.xml` — допустим только
   `split` без `DisplayFile`, если таковой остался осознанно; `grep -rn
   'displayNotFoundFile' app/src/main/java/ru/fgk/ws/app/container` — пусто.
4. Неиспользуемые ключи messages контейнерного раздела: для каждого
   удалённого/переименованного в T11–T13 ключа проверить `grep` по
   `src/main`.
5. Дефекты чинить здесь, повторно прогоняя затронутые UI-тесты.
6. `contracts.md`: раздел «Пересмотр UI 2026-09-16» — фактические id вкладок
   и имена; устаревшие пункты раздела «Карточка контейнера и вкладки»
   помечены.

## Критерии приёмки

- C1: `./gradlew :app:test` — контейнерный пакет `ru.fgk.ws.app.container.*`
  зелёный целиком; состав падений легаси-классов не изменился относительно
  [T08/checks/002.md](../T08/checks/002.md). `./gradlew spotlessCheckAll` —
  BUILD SUCCESSFUL.
- C2: Браузер, роль `container-edit`: сценарии 1–2 инструкции — создать
  контейнер (вкладки включаются после «Сохранить»), из вкладки «Ремонты»
  создать ремонт с PDF (пять вкладок, просмотр появился), из списка
  освидетельствований создать запись с актом, во вкладке «Файлы» добавить
  файл и увидеть просмотр при выборе. Роль `container-read`: те же экраны
  открываются, редактирования нет.
- C3: За проход в серверном логе нет `ERROR`; в консоли браузера нет 403 на
  `/img/**` и сырых `msg://` на экранах раздела.
- C4: Механические проверки шага 3–4 пусты; `contracts.md` соответствует коду.

## Самопроверка исполнителя

Шаги 2–4 и `./gradlew :app:test --tests "ru.fgk.ws.app.container.*"`; при
правках дефектов — затронутые UI-тесты. Полный прогон и браузерный сценарий —
проверяющему.

`task-close` по всей работе.
