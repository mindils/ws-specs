### F01.1 — формулировка «по решению пользователя» в комментарии XML

Критерий: раздел протокола «Комментарии в коде» — в коде не остаётся ссылок на
артефакты работы, в том числе формулировок «решение пользователя».
Воспроизведение: в worktree `../worktrees/rvk-ws/cyan-fennel/rvk-ws` поиск по
изменённым файлам T12 с нормализацией переносов строк (построчный `grep` эту
формулировку не видит — она разорвана переносом):

```bash
python3 - <<'PY'
import re
f='app/src/main/resources/ru/fgk/ws/app/container/view/containerrepair/container-repair-detail-view.xml'
t=re.sub(r'\s+',' ',open(f,encoding='utf-8').read())
for m in re.finditer(r'решени\w* пользовател\w*', t):
    print(t[max(0,m.start()-90):m.end()+40])
PY
```

Ожидалось: комментарий объясняет «почему» так, чтобы это понял читатель кода,
не видевший ни работы, ни её документов — без ссылки на решение пользователя
этой работы.
Получено: комментарий перед `formLayout id="documentsForm"` (вкладка «Документы
и стоимость»):

```xml
<!-- Стоимости вводятся вручную из счёта-фактуры и ничем не пересчитываются: по решению
     пользователя автоматических расчётов в разделе нет. -->
```

Доказательство: [checks/001.md](../checks/001.md), раздел «10. Комментарии в
коде».

Комментарий достался от T07 и переехал вместе с полями стоимостей при
перекомпоновке формы; файл входит в область T12, поэтому правка делается здесь.
Первое предложение комментария полезно и должно остаться — уточнить нужно только
вторую часть: например, что в разделе ремонтов контейнеров автоматических
расчётов нет вообще, поэтому НДС и итог не выводятся из стоимости ремонта.
