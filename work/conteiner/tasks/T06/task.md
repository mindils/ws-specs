## Результат и контекст

Ручные формы договоров и гарантий, необходимые для ремонтов и актов T07. Это основные бизнес-записи с правами редактора данных; справочниками, доступными только НСИ-редактору, являются их виды. Новые самостоятельные пункты основного меню для договоров/гарантий не добавлять.

Вход: [матрица договоров/гарантий](../../contracts.md#договоры-гарантии-ремонты-и-акты), [исходные поля](../../input/issue.md), фактическая модель T01 и lookup/история/роли T02. Этот таск не зависит от T03; использовать общие механизмы истории T02.

## Реализация

- Применить skills list/detail, dialog-detail-flow, service, fetch-plan, resource-role, i18n, тестов/проверок. При использовании фрагмента — соответствующий skill.
- Договор: номер, тип, дата начала/окончания действия, дата подписания, контрагент. Все даты — бизнес-даты и не удаляются вместе со старыми `recdatebegin/recdateend`.
- Гарантия: договор, вид, продолжительность в месяцах, начало гарантии как ссылка на вид акта, продление после ремонта как bool, осмотр за N суток, штраф decimal, обобщённая характеристика контейнера. Не превращать начало гарантии в дату и не вычислять срок/штраф автоматически.
- Создать lookup-списки и общие detail-формы с действиями создания, выбора, просмотра, редактирования, копирования и soft delete. Из формы договора обеспечить переход к его условиям гарантии; T07 использует те же формы из ссылочных полей.
- Контрагент — только текущий НСИ РВК. Виды актов/договоров/гарантий и обобщённые характеристики — новые справочники T02. Существующие wagon/1C/Diadoc-договоры не подменяют новые контейнерные договоры лишь из-за похожего названия.
- Запретить удаление используемого договора/гарантии по всем действующим ссылкам модели. Не добавлять автоматическую проверку применимости гарантии к ремонту: условия пользователь выбирает вручную.
- Подключить историю, поиск/фильтры/экспорт lookup-списков и права. Фактические контроллеры/view-id/поток выбора задокументировать для T07. Читатель открывает только просмотр, НСИ-роль сама по себе не меняет договоры.

## Критерии приёмки

- C1: Все поля договора и гарантии сохраняются и читаются повторно; формы доступны из lookup и не требуют старых таблиц/идентификаторов.
- C2: Начало гарантии является видом акта; её длительность/осмотр/штраф/продление сохраняются буквально, без расчётов.
- C3: Бизнес-даты договора остаются; технических полей старой историчности в формах нет.
- C4: Редактор данных ведёт договоры/гарантии, но не виды; читатель только просматривает. НСИ-роль не получает неявный CRUD основных записей.
- C5: История полная, копирование не переносит историю/id, cancel не сохраняет изменения, soft delete используется только при отсутствии действующих зависимостей.
- C6: Контракт выбора/открытия документирован для T07; пустой справочник позволяет уполномоченному пользователю создать запись через рабочую форму, не через SQL.
