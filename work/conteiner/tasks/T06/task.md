# T06 — Договоры, гарантийные условия, акты

Статус: done
План: [plan.md](../../plan.md)
Зависимости: [T02](../T02/task.md)
Сложность: medium — три пары list/detail по образцам, у акта мультивыбор
контейнеров через таблицу связи.
Сложность проверки: medium — тесты плюс браузерный проход трёх форм и ролей.
Актуальная проверка: [checks/001.md](checks/001.md)

## Коротко

Делаем страницы «Договоры», «Гарантийные условия» и «Акты» в разделе
«Контейнеры»: формы с полями старой системы, выбор контрагента из НСИ,
условия гарантии с подписью, содержащей ИД, акт с набором контейнеров.
Ремонты (T07) будут выбирать договор и два условия гарантии из этих форм.

## Результат и контекст

Договоры и гарантии — основные записи редактора данных (не НСИ). Поля —
раздел «Основные таблицы» [contracts.md](../../contracts.md) (`cnt_contract`,
`cnt_warranty`, `cnt_act`, `cnt_act_container`); подписи — «Подписи и lookup»;
поведение актов — «Карточка контейнера и вкладки» (вкладка «Акты» делается в
T07, здесь — самостоятельные экраны и форма акта). Договоры и гарантии
заводятся из UI: перенос данных старой ЕРК вынесен в отдельную работу
([Q02](../../questions/Q02.md)).

## Область и изоляция

Меняет: `container/view/{containercontract,containerwarranty,containeract}/`,
политики в `container/security` (добавление), `menu.xml` (три пункта),
messages, тесты. Общие ресурсы: БД, порт 8080, браузер, MinIO. Параллельно с
T03. Проверки после T03.

## Реализация

- Skills: `jmix-create-list-view`, `jmix-create-detail-view`,
  `jmix-add-dialog-detail-flow`, `jmix-configure-fetch-plan`,
  `jmix-add-i18n-keys`, `jmix-create-resource-role`, `jmix-create-test`.
- Договор: list (фильтры номер/тип/контрагент/даты) и detail с полями и гридом
  его условий гарантии (loader по `contract.id`, диалог создания условия с
  предустановленным договором). Контрагент — `entityComboBox` по `VOrgPassport`.
- Условие гарантии: list и detail; договор обязателен в UI; начало гарантии —
  выбор вида акта; штраф `BigDecimal`; подпись `"<id> — <договор> / <вид>"`.
- Акт: list и detail с шапкой (номер обязателен в UI, тип, договор, дата
  подписания, комментарий, документ `FileRef`) и гридом контейнеров
  (`cnt_act_container`): добавить через lookup `cnt_Container.list` (если T03
  ещё не done — через `entityPicker` с `entity_lookup` на тот же view-id,
  проверка после T03), убрать; дубли пары не допускаются. Сохранение шапки и
  связей — одной транзакцией (`DataContext`).
- Все три списка — lookup-совместимы (`@LookupComponent`), т.к. T07 выбирает
  из них. Действие «Копировать» у договора. Удаление — soft delete; при
  DENY-ссылках — сообщение.
- Политики: view-id list/detail трёх сущностей в read (просмотр) и edit
  (CRUD), menu-id пунктов.

## Критерии приёмки

- C1: Все поля договора, условия и акта сохраняются и перечитываются; формы
  доступны из меню и как lookup.
- C2: В форме договора создаются два условия; их подписи содержат id; начало
  гарантии — вид акта; ничего не пересчитывается.
- C3: Акт с контейнерами A и B сохраняется одной транзакцией; повторное
  добавление A отклоняется; удаление связи не удаляет контейнер.
- C4: Удаление договора с условиями/актами и условия, на которое ссылается
  ремонт (через `DataManager` в тесте), отклоняется.
- C5: Роль edit ведёт записи, read только просматривает, NSI-роль не имеет
  доступа к изменению; cancel не сохраняет.
- C6: Снят 2026-09-15 вместе с выносом переноса начальных данных в отдельную
  работу ([Q02](../../questions/Q02.md)); отображение договоров и условий
  покрыто C1–C3 на данных, заведённых из UI.
