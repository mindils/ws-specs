# T10 — Начальные данные из старой ЕРК

Статус: blocked
План: [plan.md](../../plan.md)
Зависимости: [T01](../T01/task.md)
Сложность: easy — liquibase `loadData` по образцам, без логики.
Сложность проверки: easy — SQL-подсчёт строк и запуск миграций.
Актуальная проверка: нет

## Коротко

Загружаем в новые таблицы значения 13 справочников, договоры и гарантийные
условия из старой системы, чтобы операторы сразу видели привычные «Текущий
ремонт», «Документ к ремонту», договоры ФГК-47-15/79-9 и условия гарантии с
известными ИД. Данные приходят выгрузками пользователя по
[Q02](../../questions/Q02.md).

## Результат и контекст

Старые числовые ИД сохраняются как `id` (решение пользователя): условие
гарантии 385331 должно открываться под этим номером. Сами контейнеры, файлы,
ремонты и история не загружаются. Выгрузки лежат в `input/seed/*.csv`
(UTF-8, заголовок, разделитель `;`).

## Область и изоляция

Меняет: `liquibase/changelog/04-data/cnt/*.csv`, `04-data/cnt_seed.xml`;
при необходимости — структура `cnt_warranty_type` в T01-changelog (по DDL из
Q02, с отдельным `addColumn` и preConditions). Общий ресурс: БД. Параллельно с
T02, T09; проверки после T09.

## Реализация

- Skill `jmix-create-liquibase-changelog`. Образцы `04-data/` проекта.
- CSV скопировать в ресурсы как есть (без персональных данных); `loadData` с
  явными `id`, `relativeToChangelogFile`, типы колонок указать явно
  (`NUMERIC`, `DATE`, `BOOLEAN`, `STRING`). preConditions: таблица пуста
  (`sqlCheck expectedResult="0"`), `onFail="MARK_RAN"`.
- Порядок: справочники → договоры → гарантии (ссылки по id). После загрузки
  `setval` для identity-последовательностей каждой таблицы на `max(id)`.
- Аудит: `created_by = 'seed'`, `created_date = now()`, `version = 1`,
  `deleted_date` NULL.
- Договоры: `org_id` записать как есть; сверить по присланной выборке
  `org_id/okpo` с `VOrgPassport` в корпоративной БД (если доступна) и
  результат записать в result.md. Локально организаций нет — это не дефект.
- `cnt_warranty_type`: структуру взять из DDL Q02; если полей больше минимума,
  дополнить entity T01 и матрицу.

## Критерии приёмки

- C1: После миграций на чистой схеме количество строк в каждой таблице равно
  числу строк CSV; выборочные записи совпадают по значениям.
- C2: `cnt_warranty` с id 385331, 786974, 786975 существуют и ссылаются на
  договоры «ФГК-47-15» и «ФГК-79-9».
- C3: Повторный запуск миграций ничего не дублирует; вставка новой записи через
  UI получает id больше максимального загруженного.
- C4: Загруженные записи открываются в экранах T02 без ошибок отображения.

## Самопроверка исполнителя

Запуск тестов любого одного класса (`--tests`) для применения миграций на
схеме worktree; SQL-подсчёт строк; проверка `setval`. Полный `:app:test` не
нужен.

## Независимая проверка

Чистая схема → миграции → подсчёты C1–C3 через SQL; открыть два справочника
и условие 385331 в UI (после done T02/T06 — из формы ремонта в T07/T08).
