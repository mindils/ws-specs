## Результат и контекст

Пользователь с ролью НСИ может вести все новые справочники из contracts.md. Основные формы смогут выбирать эти значения и существующие организации/станции. Созданы три согласованные ресурсные роли без автоматического назначения пользователям.

Вход: [матрица и права](../../contracts.md), фактическая модель и result.md проверенного T01. НСИ создаются пустыми; количества записей старой системы не являются требованием миграции.

Термин пользователя «справочник контейнеров» обозначает также сам реестр конкретных контейнеров. Его ручное создание делает T03 с правами редактора основных данных; данный таск не заменяет его справочником типов. Общие НСИ вагонов/контейнеров не дублируются: перед созданием нового справочника проверить соответствие текущим данным по contracts.md и результату T01.

## Критерии приёмки

- C1: Все 13 назначений справочников матрицы покрыты доступными list/detail и локализацией для новых НСИ либо документированным переиспользованием полностью совместимого общего НСИ; значения выбираются по внутренним id, общая запись может использоваться многими контейнерами. Не создавать копии существующих организаций/станций/дорог.
- C2: Роль ведения НСИ создаёт/изменяет/копирует/soft-delete неиспользуемую запись. Удаление используемой записи запрещено сервисом и понятно отображается.
- C3: Роль ввода выбирает НСИ, но не меняет их; роль просмотра имеет только чтение/экспорт. Прямое открытие detail не обходит права. Существующий НСИ не становится редактируемым из новой роли.
- C4: История НСИ показывает полные версии; при изменении подписи прошлые снимки сохраняются.
- C5: Все lookup организаций/станций работают с реальным НСИ; отсутствие значения не запускает скрытое создание организации.
- C6: Поиск/фильтры/настройки/экспорт работают и не показывают служебные исторические поля. Нет сырых msg:// и неизвестных view.

## Проверка

Выполнить [гейты и браузерный порядок](../../plan.md#проверка-и-передача). Записать статический вердикт каждого созданного файла.

В браузере под ролью НСИ создать хотя бы одну запись каждого справочника, проверить все его поля и связанные lookup; повторно открыть; изменить; просмотреть историю. Для моделей проверить четыре количества, для размеров — подпись «Длина (фут)», для видов гарантий — id/название без выдуманной бизнес-логики. Под ролями просмотра и ввода проверить невозможность записи, включая прямые маршруты и программный доступ.

Проверить экспорт с выбранными колонками и фильтрами. Проверить существующие lookup организаций/станций; отсутствие данных локального НСИ описать фактически, не выдавать пустой список за проверенный выбор.

Команды: `./gradlew :app:compileJava`, целевые integration/UI tests с записанными именами, `./gradlew :app:test`. После них последовательно браузер.
