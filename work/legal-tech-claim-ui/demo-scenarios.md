# Демо-набор: что проверять и как

Памятка к разделу «Претензии по технологическим неисправностям»
(`legal_tech_claim`). Работа закрыта — см. [summary.md](summary.md); здесь
только то, что нужно, чтобы своими руками посмотреть раздел в работе.

## Как получить данные

```bash
(cd docker && docker compose up -d)   # PostgreSQL на localhost:5432
./gradlew :app:test                   # накатывает демо-набор
./gradlew :app:bootRun                # приложение
```

Демо-набор заводит Liquibase тестового контура
(`app/src/test/resources/ru/fgk/ws/app/liquibase/test-changelog/040-legal_tech_claim-demo-data.xml`),
сроки досчитывает `TechClaimDemoDataIT` боевым `TechClaimDeadlineService`.
`bootRun` сам по себе демо-данных не создаёт, в прод они не попадают.

Набор **пересоздаётся при каждом прогоне тестов** от текущей даты БД:
подсветка просрочки всегда актуальна, но ручные правки в демо-карточках
сбрасываются. Ввели что-то, что хочется сохранить, — не гоняйте `:app:test`.

Вход — `/local-login`, пароль у всех троих `demo`:

| Логин | Роль | Что может |
|---|---|---|
| `demo-deps` | `legal-tech-claim-deps` | Правит зону ДЭПС, зону ДЮ видит read-only |
| `demo-du` | `legal-tech-claim-du` | Наоборот |
| `demo-adm` | `legal-tech-claim-admin` | Обе зоны + редактирование НСИ сроков |

Под существующим `user` разграничение зон не видно: у него
`system-full-access`, там всё доступно на запись.

## Что за раздел

Претензия по технологической неисправности ведётся двумя подразделениями в
одной карточке. **ДЭПС** собирает документы по отцепке и ведёт
допретензионную работу, **ДЮ** предъявляет претензию контрагенту и ведёт
судебную работу. Чужая зона у каждого read-only — это не отдельный экран, а
права на атрибуты.

По претензии считаются **сроки семи этапов** — от прикрепления комплекта
документов до подачи искового заявления. Считаются в рабочих днях по
производственному календарю НСИ (наполнен по 2026-12-31), от исходных дат
самой претензии. У каждого срока три порога просрочки: +1, +10 и +30 рабочих
дней, им соответствуют жёлтая, оранжевая и красная подсветка ячейки в списке.
Отдельный признак «Требуется пересчёт» означает, что строки расчёта нет вовсе
либо он выполнен не по последней опубликованной ревизии НСИ.

Этап может быть **не назначен** — это не то же самое, что «просрочки нет»:
условия назначения у каждого этапа свои (аренда вагона, подразделение
допретензионной работы, результат рассмотрения и т. д.).

## Карта демо-набора

Девять отцепок, десять претензий, номера вагонов 56000001…56000009.

| Вагон | Что в нём | Зачем |
|---|---|---|
| 56000001 | исходных дат нет | Заготовка «с нуля»: ни один этап не назначен |
| 56000002 | комплект документов вчера | Срок есть, просрочки нет |
| 56000003 | комплект 10 дней назад | Степень 1 — жёлтая |
| 56000004 | комплект 30 дней назад | Степень 2 — оранжевая |
| 56000005 | комплект 90 дней назад, суммы | Степень 3 — красная |
| 56000006 | полный цикл ДЭПС → ДЮ | Все семь этапов, все четыре вкладки заполнены |
| 56000007 | две претензии (1 и 2) | Нумерация претензий по отцепке |
| 56000008 | «не подлежит претензии» | Назначен только первый этап |
| 56000009 | как 56000004 | «Требуется пересчёт» при заполненных сроках |

## Сценарии

### С1. Список и подсветка сроков

Меню → «Претензии по технологическим неисправностям». Отсортировать грид по
колонке «№ вагона» — демо-строки идут подряд. Фильтр по номеру вагона работает
по точному совпадению, маски в нём нет.

**Ожидается:** в колонке срока прикрепления комплекта документов вагоны
56000002 → 56000003 → 56000004 → 56000005 дают ряд «без подсветки → жёлтая →
оранжевая → красная». Колонка степени просрочки показывает текст, а не
`msg://`.

### С2. Расчёт с нуля

Открыть карточку 56000001 под `demo-deps`. Вкладка «Сроки» пустая — ни один
этап не назначен. Заполнить на вкладке «Документы» поле **«Дата формирования
полного комплекта документов»** (любая дата в пределах 2026 года), сохранить,
открыть карточку снова.

**Ожидается:** на вкладке «Сроки» появился срок первого этапа с порогами.
Расчёт запускается сам при сохранении — отдельной кнопки нет.

### С3. Полная карточка

Открыть 56000006 под `demo-adm` и пройти по пяти вкладкам: «Документы»,
«Допретензионная работа», «Претензия», «Судебная работа», «Сроки».

**Ожидается:** заполнены все четыре рабочие вкладки; на вкладке «Сроки» семь
строк, у всех есть срок; даты на вкладке совпадают с колонками списка по этой
же строке.

### С4. Неприменимый этап против неактуального расчёта

Сравнить в списке три строки:

- **56000008** — срок есть только у первого этапа, остальные шесть пустые:
  претензия не подлежит предъявлению, этапы не назначаются;
- **56000001** — пусты все семь: исходных дат нет;
- **56000009** — сроки заполнены, но стоит признак **«Требуется пересчёт»**:
  расчёт сделан по старой ревизии НСИ.

**Ожидается:** пустой срок и «Требуется пересчёт» — это разные состояния, и
по гриду видно какое где.

### С5. Дополнительная претензия

Встать на строку вагона 56000007 под `demo-deps` или `demo-adm`, нажать
**«Создать претензию»**.

**Ожидается:** по отцепке появилась третья претензия (`claim_index = 3`) с
пустой карточкой; две прежние на месте. Под `demo-du` кнопки «Создать
претензию» в тулбаре нет вовсе — она скрыта по праву CREATE.

### С6. Разграничение зон

Открыть одну и ту же карточку (удобно 56000006) последовательно под
`demo-deps` и `demo-du`.

**Ожидается:** под `demo-deps` вкладки «Документы» и «Допретензионная работа»
редактируются, «Претензия» и «Судебная работа» read-only. Под `demo-du` —
ровно наоборот. Под `demo-adm` редактируется всё.

### С7. Фильтры

Применить по очереди: номер вагона, диапазон дат браковки, степень просрочки
по одному из этапов.

**Ожидается:** счётчик строк меняется под каждый фильтр. Фильтр степени
просрочки по этапу прикрепления комплекта документов на демо-наборе даёт:
степень 1 — вагоны 56000003 и 56000006; степень 3 — только 56000005.

## Если что-то не так

- **Список пуст** — не прогонялись тесты после пересоздания БД. `./gradlew :app:test`.
- **Приложение не стартует, «Supported database is not determined from JDBC URL»**
  — не поднят Docker с PostgreSQL либо не создан
  `app/src/test/resources/application-test-local.properties` с локальным JDBC URL.
- **Все строки помечены «Требуется пересчёт»** — демо-пересчёт выполнился не
  последним. Он должен идти после тестов, публикующих ревизию НСИ; порядок
  задаёт `ru.fgk.ws.app.test_support.DemoLastClassOrderer` через
  `app/src/test/resources/junit-platform.properties`. Разовое лечение:
  `./gradlew :app:test --tests "ru.fgk.ws.app.it.TechClaimDemoDataIT"`.
- **Расчёт отказывается с сообщением о недостающем дне календаря** — дата
  ушла за 2026-12-31. Производственный календарь на 2027 год не наполнен
  ([Q01](questions/Q01.md)), это ожидаемое поведение.
