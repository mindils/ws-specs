## Коротко

Все части раздела готовы по отдельности; этот таск проходит цепочку целиком
глазами пользователей: ДЭПС ведёт претензию до передачи в претензионную
работу, ДЮ доводит её до суда и оплаты, сроки и подсветка живут в списке и
карточке, календарь и нормы пересчитывают сроки при публикации. По итогу
обновлены документы спеки и работа готова к закрытию.

## Реализация

1. Фикстуры: SQL-скрипт `checks/fixtures_e2e.sql` (в транзакции либо с
   явной очисткой) — отцепка с претензией и `du`, ещё ≥ 60 претензий для
   пагинации со степенями просрочки 0/1/2/3 по разным этапам, одна с
   устаревшей ревизией, одна без расчёта.
2. Сценарий браузером (`playwright-cli` или агент `qa`): ДЭПС создаёт
   вторую претензию по отцепке, заполняет «Документы» (дата комплекта,
   передача документов) и «Допретензионную работу» (передача в
   претензионную), сохраняет → в списке появились сроки и подсветка; ДЮ
   открывает ту же претензию, вкладки ДЭПС read-only, заполняет «Претензию»
   (дата, отправка, ответ) и «Судебную работу», сохраняет → сроки судебных
   этапов появились; фильтры по степеням и срокам на выборке > страницы
   дают верный count; смена дня — эмулируется фикстурой с порогами
   относительно `current_date` (часы не переводить); публикация ревизии
   после правки календаря через экран НСИ пересчитывает сроки и снимает
   признак «Требуется пересчёт».
3. Полные гейты: `./gradlew :app:test` (`0 failing`), инспекция IDE по всем
   файлам работы (или запись, что недоступна), render-проход.
4. Документы: README спеки — имена `legal_tech_claim*`, ссылка на
   `specs/work/legal-tech-claim-ui/`, пометка об устаревшем `04-new-model.md`;
   документ отличий — фактические даты демонстрации примеров из его таблицы
   на реальном календаре 2026 года (без выдуманных праздников).

## Критерии приёмки

- C1: сквозной сценарий ДЭПС → ДЮ пройден в браузере без ошибок; обе записи
  в БД содержат введённые значения.
- C2: семь сроков и степени согласованы между списком, вкладкой «Сроки» и
  таблицей расчёта для проверяемой претензии.
- C3: фильтры по срокам/степеням/суммам и count верны на выборке > страницы;
  «Требуется пересчёт» отличает отсутствующий/устаревший расчёт от
  неприменимого этапа.
- C4: публикация ревизии календаря пересчитывает сроки существующих
  претензий; ошибка пересчёта не публикует ревизию (негативный сценарий из
  `TechClaimDeadlineIT` подтверждён прогоном).
- C5: `./gradlew :app:test` — `0 failing`; render-проход всех view раздела
  под ДЭПС и ДЮ — без error overlay, серверных исключений и сырых `msg://`.
- C6: README и документ отличий обновлены; поиск `warranty_repair` и
  `WarrantyRepair` по `specs/dr-warranty-repair/README.md` и документу
  отличий находит только упоминания истории переименования.
