5. Независимый SQL-сценарий в транзакции с `rollback`:
   Создана тестовая отцепка и четыре претензии:
   - Претензия 1: актуальная опубликованная ревизия НСИ, строки в `_du` и
     `_case_one`, пороги 7 этапов расчёта в разных положениях относительно
     `current_date` базы.
   - Претензия 2: устаревшая ревизия (номер 0).
   - Претензия 3: без строки расчёта в `legal_tech_claim_deadlines`.
   - Претензия 4: удалённая претензия (`deleted_date = now()`).

   Результаты запросов к view:
   - C1: во view отобразились ровно 3 не удалённые претензии (1, 2, 3).
     Удалённая претензия 4 во view не попала (`deleted_claims_visible = 0`).
   - C3: для претензии 1 проверены все 7 сроков и степени:
     - `doc_attach`: порог в будущем -> степень `NULL`;
     - `pre_claim_transfer`: дата БД ровно на пороге level1 -> степень `1`;
     - `pre_claim_letter`: дата БД ровно на пороге level2 -> сохранена
       степень `1`;
     - `claim_transfer`: дата БД ровно на пороге level3 -> сохранена степень `2`;
     - `claim_submit`: дата БД за порогом level3 -> степень `3`;
     - `law_transfer`: даты не назначены (неприменимый этап) -> срок `NULL`,
       степень `NULL`;
     - `lawsuit_submit`: иск подан в прошлом (`du.lawsuit_date`), факт до
       первого порога -> степень `NULL`.
   - C4: `deadlines_outdated` равен `false` для претензии 1, `true` для
     претензии 2 (устаревшая ревизия) и `true` для претензии 3 (без расчёта).
   - C5 и регрессия сумм:
     - претензия 1: `downtime_penalty_cost` = 10500.00 (7 * 1500.00),
       `tariff_rebill_total_calc` = 23000.7500, `total_reimbursement` =
       83500.7500, `underpaid_cost` = 38500.75, `defect_code_123` =
       '205+000+000', `claim_deadline_date` = '2026-03-15';
     - претензии 2 и 3: `total_reimbursement` равен сумме указанных слагаемых,
       незаполненные поля возвращают `NULL`.
   После завершения проверок выполнен `rollback`.
