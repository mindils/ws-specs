# Q02 — Ошибка «Обработать повторно» и неработающая галочка связанных документов

Статус: resolved
Затронутые таски: [T01](../tasks/T01/task.md), [T04](../tasks/T04/task.md), [T06](../tasks/T06/task.md)
Блокирует: нет — решения приняты, объём оформлен исправлениями T01/F01 и T04/F01

## Вопрос и факты

Пользователь проверил результат работы на карточке пакета Диадок
(`DiadocPacketDetailView`) и сообщил два дефекта (чат, 2026-09-21):

1. Кнопка «Обработать повторно» даёт уведомление «Ошибка обработки» с
   текстом `You have attempted to set a value of type class java.lang.String
   for parameter entityId with expected type of class java.lang.Long from
   query string select e from nsi_DiadocContractor e where e.id = :entityId`.
2. Галочка «Показать связанные документы» у администратора видна, но не
   работает. Ожидание: обычный пользователь видит состав по настройке
   контрагента, администратор может управлять показом; вместо галочки
   нужна кнопка «Показать связанные» / «Скрыть связанные», размещённая
   удобнее.

Установлено разбором кода (приложение не запускалось):

- Ошибка 1. `DiadocPacketDetailView.onRefreshPacketTypeClick` после
  успешной перенаработки вызывает `refreshEditedEntity()`, который грузит
  `DiadocPacket` без fetch plan (`dataManager.load(DiadocPacket.class)
  .id(..).one()`), кладёт его в `packetDocumentDc` и зовёт `setupView()`.
  Тот выполняет `applyShowRelatedSettings()` →
  `DiadocProcessingSettingsService.resolveForPacket(packet)` →
  `packet.getContractor()`. Ссылка `DiadocPacket.contractor` джойнится по
  `contractor_code → code`, а не по первичному ключу, поэтому ленивая
  подгрузка Jmix ищет контрагента по `id` со строковым значением кода и
  падает `IllegalArgumentException`; обработчик кнопки ловит `Exception`
  и показывает «Ошибка обработки». Сама перенаработка (`reprocess` →
  `parsePacket`) проходит: `DiadocLocalPacketService.load` берёт
  `contractor` в fetch plan. Риск был отмечен в `T04/result.md`
  («Ограничения»), но закрыт только fetch plan-ом контейнера в XML, а не
  в перезагрузке после кнопки.
- Ошибка 2 (предположение, подтвердить воспроизведением в T04/F01).
  Чекбокс — `HasValueAndElement`. `StandardDetailView` переводит экран в
  режим «только чтение», когда у пользователя нет UPDATE на
  `diadoc_DiadocPacket` (`InMemoryCrudEntityContext.isUpdatePermitted` →
  `setReadOnly(true)`; проверено по байткоду `jmix-flowui-3.0.0`), а
  `ReadOnlyViewsSupport` ставит `setReadOnly(true)` всем полям экрана.
  Роли проекта дают на `DiadocPacket` только READ
  (`DiadocShowPacketDocumentsRole`, `AiChatUserRole`), поэтому
  администратор настроек без `system-full-access` получает
  заблокированную галочку. Проверка T04 делалась под `admin` с полным
  доступом и потому дефект не увидела. `JmixButton` с clickListener в этом
  режиме работает — пример на той же карточке: «Обработать повторно».

## Варианты и рекомендация

По ошибке 1 — техническое решение без вариантов для пользователя: сервис
настроек не должен зависеть от ссылки `contractor`, а перезагрузка после
кнопки — от fetch plan по умолчанию.

По кнопке — вопрос семантики:

1. Кнопка только переключает состав на открытой карточке (рекомендовано:
   согласовано планом, объём минимальный).
2. Кнопка ещё и сохраняет `showRelatedDocuments` в строку контрагента
   пакета — нужна запись из карточки, создание строки из умолчаний,
   решение для пакетов без контрагента.

## Ответ пользователя

Кнопка только переключает состав на экране (вариант 1), настройку
контрагента не пишет.

## Ответ и основание

Принято (ответ пользователя 2026-09-21, техническое решение резолвера):

- `DiadocProcessingSettingsService` дополняется методом
  `resolveByContractorCode(@Nullable String code)` — строка
  `DiadocSignSettings` по `e.contractor.code = :code`, иначе умолчания;
  `resolveForPacket(packet)` переводится на `packet.getContractorCode()`
  (String-колонка `contractor_code`, всегда в `_base`). Метод
  `resolve(@Nullable DiadocContractor)` остаётся, контракт T02 не
  меняется. Основание: ссылка по неключевой колонке не поддерживает
  ленивую подгрузку, а пакет приходит в сервис из разных загрузчиков.
- `refreshEditedEntity()` на карточке перезагружает пакет с fetch plan
  контейнера (`packetDocumentDl.load()` либо явный fetch plan с
  `contractor`), чтобы item всегда соответствовал плану, объявленному в
  XML.
- Чекбокс заменяется кнопкой-переключателем: состояние — поле контроллера
  `boolean showRelated`, инициализируется из настройки контрагента;
  кнопка видна только при `DiadocSettingsEditEnabled`; нажатие меняет
  только состав на экране. Текст по состоянию: «Показать связанные
  документы» / «Скрыть связанные документы» (ключи
  `showRelatedButton.show` / `showRelatedButton.hide`, ключ
  `showRelatedCheckbox.label` удаляется). Размещение — компактная строка
  над гридом состава (`hbox`, `justifyContent="END"`,
  `themeNames="small"`); иконка — только реальная константа `VaadinIcon`
  (`LINK` / `UNLINK`, проверить через `jmix-verify-api-symbol`) либо без
  иконки. `filterDocuments(List, boolean)` и его unit-тест сохраняются.

Последствия: T01 и T04 возвращаются в работу исправлениями; T06 не
переделывается, но его критерий C3 (карточка) устаревает и
переподтверждается после `done` у обоих исправлений; критерий работы про
галочку переформулирован на кнопку.
