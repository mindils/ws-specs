## Замечания

### F01.1 — resolveForPacket падает на пакете, загруженном без contractor

Критерий: C2 (резолв настроек для пакета) и общий контракт сервиса из
плана
Воспроизведение: загрузить пакет без fetch plan на ссылку —
`dataManager.load(DiadocPacket.class).id(<messageId>).one()` — и вызвать
`DiadocProcessingSettingsService.resolveForPacket(packet)`. В приложении
так делает `DiadocPacketDetailView.refreshEditedEntity()` после кнопки
«Обработать повторно».
Ожидалось: настройки контрагента пакета (или умолчания) независимо от
того, каким загрузчиком пришёл пакет.
Получено: `IllegalArgumentException: You have attempted to set a value of
type class java.lang.String for parameter entityId with expected type of
class java.lang.Long from query string select e from nsi_DiadocContractor e
where e.id = :entityId`.
Доказательство: `DiadocPacket.contractor` объявлен с
`@JoinColumn(name = "contractor_code", referencedColumnName = "code")`;
ленивая подгрузка Jmix ищет контрагента по значению FK как по `id`,
поэтому `packet.getContractor()` вне fetch plan падает. Разбор — в
[Q02](../../../questions/Q02.md).

Исправление (решение Q02): добавить
`DiadocProcessingSettings resolveByContractorCode(@Nullable String code)` —
строка `DiadocSignSettings` по запросу
`select e from DiadocSignSettings e where e.contractor.code = :code`
(`maxResults(1)`), при `null`/пустом коде или отсутствии строки —
умолчания; `resolveForPacket(packet)` переводится на
`packet.getContractorCode()`. `resolve(@Nullable DiadocContractor)`
остаётся без изменений. Javadoc сервиса — почему резолв идёт по коду
(ссылка по неключевой колонке не поддерживает ленивую подгрузку).

Тест: новый кейс в `app/src/test/java/ru/fgk/ws/app/it/DiadocProcessingSettingsIT.java`
— пакет, загруженный без `contractor` в fetch plan: со строкой
контрагента → значения строки, без строки → умолчания; существующие кейсы
не меняются.
