## Замечания

### F01.1 — «Обработать повторно» с карточки завершается «Ошибка обработки»

Критерий: C1 (карточка открывается и показывает состав по настройке) и
критерий работы «Обработать повторно с карточки не даёт ошибки»
Воспроизведение: открыть карточку пакета Диадок, нажать «Обработать
повторно» (`refreshPacketType`) при доступном rvk-diadoc.
Ожидалось: уведомление «Документ успешно обработан», карточка
перечитывается.
Получено: уведомление «Ошибка обработки» с текстом `You have attempted to
set a value of type class java.lang.String for parameter entityId with
expected type of class java.lang.Long from query string select e from
nsi_DiadocContractor e where e.id = :entityId`.
Доказательство: `onRefreshPacketTypeClick` → `refreshEditedEntity()`
грузит пакет `dataManager.load(DiadocPacket.class).id(..).one()` без
fetch plan на `contractor` и кладёт в `packetDocumentDc`; следующий
`setupView()` → `applyShowRelatedSettings()` → `resolveForPacket` →
`packet.getContractor()` → ленивая подгрузка по `contractor_code` как по
`id`. Разбор — [Q02](../../../questions/Q02.md).

Исправление: `refreshEditedEntity()` перезагружает пакет с fetch plan
контейнера — через `packetDocumentDl.load()` либо явный fetch plan
`_base` + `contractor` (как в XML `packetDocumentDc`). Корень
(`resolveForPacket` через ссылку) закрывает
[T01/F01](../../T01/fixes/F01.md); выравнивание fetch plan делается всё
равно, чтобы item контейнера соответствовал объявленному плану.

### F01.2 — Галочка «Показать связанные документы» не работает у администратора; нужна кнопка

Критерий: C1
Воспроизведение (сделать до правки и записать итог в `result.md`):
пользователь с ролями `ws-user` + `diadoc-settings-admin` без
`system-full-access`; открыть карточку пакета со связанными документами
через «Просмотр»; переключить галочку.
Ожидалось: состав грида меняется.
Получено (по сообщению пользователя): галочка видна, но не работает.
Доказательство: предположение — `StandardDetailView` переводит экран в
read-only, когда у пользователя нет UPDATE на `diadoc_DiadocPacket`
(`InMemoryCrudEntityContext.isUpdatePermitted` → `setReadOnly(true)`),
а `ReadOnlyViewsSupport` ставит `setReadOnly(true)` всем
`HasValueAndElement`, включая чекбокс; роли проекта дают на
`DiadocPacket` только READ. Проверка T04 шла под `admin` с полным
доступом и дефект не увидела. Кнопка с clickListener в этом режиме
работает («Обработать повторно» на той же карточке).

Исправление (решение Q02, ответ пользователя: кнопка только переключает
состав на экране):

- Убрать `showRelatedCheckbox` из XML и контроллера (`@ViewComponent`,
  `@Subscribe("showRelatedCheckbox")`). Состояние — поле контроллера
  `boolean showRelated`, инициализируется в `applyShowRelatedSettings()`
  из `resolveForPacket(packet).showRelatedDocuments()`;
  `filterDocuments(List)` читает это поле; статический
  `filterDocuments(List, boolean)` и `DiadocPacketDocumentFilterTest`
  сохраняются.
- Кнопка `showRelatedButton` (`JmixButton`, clickListener) видна только
  при `DiadocSettingsEditEnabled`; нажатие инвертирует `showRelated`,
  обновляет текст и делает `documentItemsDc.setItems(filterDocuments(
  allDocuments))`. Текст по состоянию: при скрытых связанных — «Показать
  связанные документы», при показанных — «Скрыть связанные документы»
  (ключи `showRelatedButton.show` / `showRelatedButton.hide` в блоке
  `ru.fgk.ws.app.diadoc.view.diadocpacket/`; ключ
  `showRelatedCheckbox.label` удалить, неиспользуемых ключей не
  оставлять).
- Размещение: компактная строка над гридом состава — `hbox` с
  `justifyContent="END"`, `width="100%"`, кнопка `themeNames="small"`;
  иконка — только реальная константа `VaadinIcon` (`LINK` при скрытых,
  `UNLINK` при показанных — проверить через `jmix-verify-api-symbol`)
  либо без иконки. Стили — по `jmix-style-ui`.
- После правки XML — инспекция дескриптора (`jmix-ide-static-analysis`).
- Если воспроизведение покажет иную причину неработающей галочки, чем
  read-only режим, записать её в `result.md`; на исправление это не
  влияет — кнопка вводится по решению пользователя.
