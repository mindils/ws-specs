## Замечания

### F01.1 — PacketReplayIT падает с NoSuchElementException из-за жестко зашитой схемы main в PacketReplayFixtures

Критерий: C1
Воспроизведение: `./gradlew :app:test --tests "ru.fgk.ws.app.it.PacketReplayIT"` в окружении схемы worktree `main_f_diadoc_check`.
Ожидалось: `PacketReplayIT` отрабатывает успешно (все 7 тестов зеленые), подтверждая корректность загрузки фикстур и отсутствие регрессий при наработке пакетов.
Получено: Все 7 тестов падают с `java.util.NoSuchElementException: No value present` на `localPacketService.load(UUID.fromString(messageId)).orElseThrow()`.
Доказательство:
`tables.txt` в ресурсах `diadoc/replay/` содержит жестко заданный префикс схемы `main` (`packet.csv main.diadoc_packet`, `packet_doc_link.csv main.diadoc_packet_doc_link` и т.д.), а в методе `PacketReplayFixtures.loadChecks` выполняется `select ... from main.dr_wag_vrk_arch where xml_hash = ?`.
В результате `fixtures.insertAll()` вставляет строки фикстур в схему `main`, тогда как Spring-контекст теста подключен к схеме `main_f_diadoc_check` (`application-test-local.properties`). При вызове `localPacketService.load(UUID)` JPA ищет пакет в `main_f_diadoc_check.diadoc_packet`, где строка с этим `messageId` отсутствует.

При временной замене жесткого префикса `main.` на активную схему подключения (`jdbcTemplate.queryForObject("select current_schema()", String.class)`) в `readIndex()` и `loadChecks` класса `PacketReplayFixtures.java` все 7 тестов `PacketReplayIT` успешно проходят:
```text
  ru.fgk.ws.app.it.PacketReplayIT
    ✔ Тип детали листа комплектации определяется (2.7s)
    ✔ Пакет ТР-2: проверки применяются, лишних сообщений нет
    ✔ Плановый пакет: стоимость подачи/уборки сверена с договором
    ✔ Деталь найдена на складе: расхождение по депо, совпадение — без замечаний
    ✔ Договор найден: договорные проверки отработали без замечаний
    ✔ Плановый пакет: проверки применяются, лишних сообщений нет
    ✔ Деталь, попавшая и в МХ-3, и в РДВ, в замены считается один раз
  7 passing (25.8s)
```
