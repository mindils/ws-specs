# Итог: описания переноса контейнеров ЕРК ↔ РВК

## Что появилось

Три документа в `specs/work/002-container-erk-migration/`:

- [mapping.md](mapping.md) — откуда и куда загружать: правила выбора
  действующих версий, ключей и системных колонок, порядок загрузки, таблицы
  «старая колонка → новая» для всех 22 таблиц `cnt_*`, что не переносится,
  сверка.
- [legacy-files.md](legacy-files.md) — как показывать файлы из старого
  хранилища без копирования (хранилище `erk`, ссылки `erk://s3/…` и
  `erk://db/…`) и как файл переезжает в S3 РВК при замене или пересохранении
  записи; фоновый перенос остатка, чтобы отключить ЕРК.
- [reverse-rvk-to-erk.md](reverse-rvk-to-erk.md) — 11 причин, почему сложно
  перегружать РВК → ЕРК, и сложность по сценариям.

Плюс записка исследования [input/research.md](input/research.md): варианты
механизма переноса, оценка объёма, SELECT-ы для разведки.

## Как пользоваться

Следующий шаг — получить ответы из «Что нужно узнать» (legacy-files.md) и
результаты SELECT-ов из research.md, затем `/rt-plan
002-container-erk-migration` на реализацию.

## Как устроено

Документы опираются на код в `main`:
- entity `app/src/main/java/ru/fgk/ws/app/container/entity/`;
- changelog-и `liquibase/changelog/01-tbl/tbl-cnt_*.xml`;
- регистрацию хранилищ `storage/FileStorageFoldersConfiguration`;
- чтение файлов `common/view/displayfile/DisplayFile` — хранилище по имени из
  `FileRef`.

## Как проверено

Имена колонок и классов сверены с entity и кодом чтения файлов. Данные ЕРК не
проверялись — доступа к БД ЕРК нет, предположения помечены в документах.
Код не менялся, тесты не запускались.

## Решено без вас

- Аудит загруженных строк: `created_by = 'erk'`, дата загрузки. Вариант с
  `user_name` старых версий оставлен на решение.
- Ссылка `FileRef` на старый файл привязана к `data_file.id`, а не к
  `file_id`: не нужно выбирать версию при чтении.
- Файлы из `bytea` советую копировать в S3 РВК сразу при переносе, ссылаться
  только на S3 ЕРК: тогда РВК не держит подключение к БД ЕРК.
- Недоступная ЕРК не роняет сохранение: ссылка остаётся `erk://`, в лог —
  предупреждение.
- Хранилище `erk` — свой класс `FileStorage`, не второй `AwsFileStorage`:
  второй такой бин уронит `FileStorageFoldersConfiguration` на старте.
- Ненайденные организации, станции и справочные значения → `NULL` + отчёт,
  строка грузится. Дети без контейнера не грузятся (`container_id` NOT NULL).
