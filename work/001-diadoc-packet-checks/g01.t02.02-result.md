## Сделано

- **Конвейер** в пакете `ru.fgk.ws.app.diadoc.check`:
  - `PacketCheckStep` — шаг: `source()`, `check(context)` → позиции; `copiesToLegacyTable()` по
    умолчанию `true` у шагов `BUSINESS`. Адаптер t03 переопределяет на `false`, тогда его позиции
    не копируются обратно в старую таблицу.
  - `PacketCheckContext` — срез, пакет, тип наработки, `PacketParseOutcome`, настройки
    контрагента. Настройки читаются при первом обращении, поэтому сбой их чтения роняет только
    шаг, которому они нужны.
  - `PacketCheckReport` — позиции, `status()`, `isNorm()`, `message()` (тексты через `\n`).
  - `PacketCheckComposition.stepsFor(type)` — явный `switch` по типам из `dispatch`: сейчас у
    каждого типа `ParseOutcomeCheckStep`, `DiadocViolationsCheckStep`. У прочих типов (СЧФ, OTHER…)
    пустой список, и строка для них не создаётся. t03 вставляет адаптер между двумя шагами.
  - `PacketCheckPipeline.checkAndStore(snapshot, type, outcome)` прогоняет шаги. Исключение шага
    превращается в позицию `PROCESSING`/`CHECK_FAILED`/VIOLATION с параметром `step` и текстом
    «Проверка не выполнена (<источник>): <причина>». Позиции `BUSINESS` из шагов с
    `copiesToLegacyTable()` копируются через `DiadocPacketCheckResultService.appendResults` (сбой
    копии только пишется в лог). Строку перезаписывает `PacketCheckService.saveDiadocCheck`, ошибка
    записи пробрасывается: иначе решение об автоподписании прочитало бы прошлую строку.
- **Шаги:** `ParseOutcomeCheckStep` (`PROCESSING`): разбор не пройден — одна позиция VIOLATION,
  код = `ProcessPacketErrorType.name()`, текст = сообщение исхода (пустое → «Пакет не
  наработан»). `DiadocViolationsCheckStep` (`DIADOC`) берёт позиции из
  `MirrorPacketViolationService.collectItems`.
- **Одна логика флагов Диадок.** `MirrorPacketViolationService.collectItems(packet[, settings |
  supplier])` выдаёт `PacketCheckItem`: код = id вида нарушения, `params` = `torDocumentId`,
  `relatedMessageIds` (через запятую). `findCalculatedResult` (чтение на лету для СЧФ и пакетов без
  строки) считается по тем же позициям. `collectResults` и `summaryCode` удалены. Настройки
  по-прежнему читаются, только если нарушения есть.
- **`PacketParserService.dispatchAndResolve`:** после парсера конвейер запускается всегда, и при
  отказе разбора тоже. Отказ разбора — ответ как раньше: `errorType`/`message` исхода. Наработан —
  `ok` только при `report.isNorm()`, иначе `CHECK_FAILED` с текстами позиций. Нет состава у типа
  (сейчас недостижимо) — `CHECK_FAILED` «Результат контроля не определён». `PACKET_NOT_FOUND`,
  неизвестный тип и типы вне `dispatch` строки не создают. Зависимости от
  `DiadocPacketCheckResultService` и `DiadocPacketViolationCheckService` у него больше нет.
- **`DiadocPacketViolationCheckService`** сокращён до того, что нужно t04: public
  `PENDING_DOCUMENT_FLOW_STATUSES`, `isSigningInProgress(link)`, `describeDocument(link)`.
  `applyTo` и `collectResults` удалены: «связанный документ в подписании» больше не нарушение.
  Ключ `violation.relatedInSigning` оставлен для текста причины в t04: используй его или удали.
- **Переходное состояние до t03:** бизнес-отметки старых таблиц в строку пока не попадают. Поэтому
  после t02 пакет с бизнес-нарушениями, но без флагов Диадок даёт `ok = true`. Это закрывает
  адаптер t03. Прежний ответ «отметки контроля нет → `CHECK_FAILED`» тоже переходит к t03: если
  в старой таблице отметки нет, адаптер должен выдать позицию, иначе `ok` станет `true`.

## Решено без вас

- Логика флагов Диадок осталась в `MirrorPacketViolationService` (там тексты и ключи
  `diadoc.service/violation.*`), шаг `DIADOC` её вызывает. Так копия одна, а тесты разбора не
  пришлось переносить.
- Признак «копировать в старую таблицу» — метод шага `copiesToLegacyTable()`; копируются только
  позиции с `source = BUSINESS`. Позиция `CHECK_FAILED` упавшего бизнес-шага не копируется.
- Ошибка записи строки `packet_check` пробрасывается (500 / `INTERNAL_ERROR`, как ошибка парсера),
  а ошибка копии в старую таблицу только пишется в лог.
- Для отказа разбора `message` ответа — текст исхода, без позиций Диадок: контракт ответа не
  меняется.
- Исключение парсера, как и раньше, уходит наружу; конвейер в этом случае не запускается.
