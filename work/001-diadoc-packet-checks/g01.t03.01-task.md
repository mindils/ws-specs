## Коротко

Шаг `BUSINESS` конвейера (t02): после парсера читает отметку контроля из таблицы типа и
раскладывает её на позиции новой таблицы. Парсеры не меняются. Правила раскладки — план, раздел
«Конвейер проверок», пункт «Бизнес-адаптер».

## Что сделать

- Адаптер для каждого типа из `PacketParserService.dispatch`; хранение и ключи по типам — как в
  `DiadocPacketCheckResultService` (переиспользуй его загрузку, не дублируй запросы).
- Код позиции `BUSINESS_<TYPE>`, уровень по колонке там, где колонки раздельные (контракты ТР-2 и
  ДЕП/КАП с текстами связей МХ и `WARNING_ECP`, Рем.Дет), иначе — по общему коду пакета.
- Вписать шаг в состав всех типов. Порядок шагов в строке: `PROCESSING`, `BUSINESS`, `DIADOC`.
- Адаптер не должен дублировать свои позиции обратно в старые таблицы (дубль из t02 — только для
  не-адаптерных бизнес-шагов).

Не трогать: парсеры, валидаторы, АСУ ВРК.

## Готово, когда

- Для каждого вида хранения отметки позиции и уровни совпадают с тем, что показывает старая
  отметка; пакет без замечаний даёт ноль позиций `BUSINESS`.
- Итог `ok` наработки совпадает с прежним для пакетов без флагов Диадок.

## Как себя проверить

- Тесты на каждый вид хранения: контракт ТР-2 (нарушения + предупреждения + связь МХ),
  план ДЕП/КАП, Рем.Дет (`errors` и `errors_warning`), ТР-1, `dr_diadoc_oper_repair_packet`.
- Последний таск группы: весь набор `./gradlew :app:test` зелёный (при падениях окружения —
  сначала compose и локальный datasource, см. `CLAUDE.md`).
