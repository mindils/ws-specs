## Коротко

Две подготовительные вещи для конвейера проверок (см. `00-plan.md`, «Общие решения»):
переименовать уровни нарушений в настройках контрагента и завести таблицу `packet_check` с entity.

## Что сделать

**Уровни нарушений** (раздел плана «Уровни нарушений в настройках контрагента»):
- `DiadocViolationLevel`: `NOT_APPLICABLE` / `VIOLATION` (`violation`, «Нарушение») /
  `WARNING` (`warning`, «Предупреждение»); `ERROR` убрать. Подписи enum, экран настроек
  `DiadocSignSettingsDetailView` (вкладка «Обработка»), remarks/комментарии.
- Новый changeSet в `tbl-diadoc_sign_settings_violation.xml`: `error` → `violation`, с
  preConditions. Старые changeSet-ы не менять.
- `DiadocProcessingSettings` и `MirrorPacketViolationService.collectResults`/`findCalculatedResult`
  учитывают уровень: Нарушение → `PackCheckResult.violation`, Предупреждение → `warning`.
  Итог `findCalculatedResult` для пакета только с предупреждениями — WARNING.

**Таблица и entity** (раздел плана «Новая таблица `packet_check`»):
- entity `PacketCheck` в `ru.fgk.ws.app.diadoc.entity`, changelog в `01-tbl/`, messages,
  чтение в ролях, которым доступна карточка пакета Диадок (`DiadocPacketDetailView`); запись идёт
  из сервисов через `UnconstrainedDataManager`/system-контекст, отдельные права на запись UI не
  нужны.
- Модель позиции и причины запрета (поля из плана) — классы в `diadoc`-пакете, которыми
  пользуются t02–t05; хранение `items`/`auto_sign_blockers` в jsonb. Удобный API чтения/записи
  позиций — на твоё усмотрение, но один на всех.
- Скилы: `jmix-create-entity`, `jmix-create-liquibase-changelog`, `jmix-add-i18n-keys`,
  `jmix-create-resource-role`.

Не трогать: `PacketParserService`, `DiadocPacketViolationCheckService` — это t02.

## Готово, когда

- На чистой схеме и на схеме с данными миграции проходят; строки `error` становятся `violation`.
- Уровень «Предупреждение» у вида нарушения даёт предупреждение, а не нарушение, в
  `MirrorPacketViolationService`.
- `PacketCheck` сохраняется и читается с позициями в jsonb; уникальность
  `source_type` + `source_key` работает.

## Как себя проверить

- `./gradlew :app:test --tests "ru.fgk.ws.app.diadoc.service.MirrorPacketViolationServiceTest"`
  и `--tests "ru.fgk.ws.app.it.DiadocProcessingSettingsIT"` — обновить под новые уровни.
- IT на changeSet `error` → `violation` по образцу `DiadocRelatedRejectedMigrationIT`.
- IT на сохранение/чтение `PacketCheck` с позициями.
- `./gradlew :app:compileJava`; дескриптор экрана настроек — инспекцией по `jmix-ide-static-analysis`.
