## Коротко

Сервис, который решает, можно ли автоматически согласовать и подписать пакет, и перевод
`/api/diadoc/approve` на это решение. Причины, документы и ответ — план, раздел «Решение об
автоподписании». Строка `packet_check`, шаг `DIADOC` и модель причин — из g01.

## Что сделать

- Сервис решения: все причины из плана, пересчёт шага `DIADOC`, обновление строки
  (`DIADOC`-позиции, `status`, `auto_sign_*`). Метод «посчитать без сохранения» для карточки
  (t05) — тоже здесь.
- Проверка «в подписании» — из `DiadocPacketViolationCheckService.isSigningInProgress` (если t02
  его оставил — перенести сюда и удалить остаток).
- Настройка автосогласования по типу — поведение как сейчас (`AUTO_APPROVAL_CODES` +
  `NvProcessingSettingsService`), только как одна из причин.
- `PacketApprovalService.approve`: `ok` из запроса игнорирует; при запрете — отказ с причинами;
  при разрешении согласует только свои документы пакета (без связанных, дополнений и удалённых
  ссылок). `ApprovePacketErrorType.AUTO_SIGN_BLOCKED`, список причин в `ApprovePacketResponse`;
  старые поля сохраняются.
- Работа в system-контексте (`PacketFlowRestController` вызывает под `SystemAuthenticator`) —
  проверь, что сервис не зависит от текущего пользователя.

Не трогать: ручное согласование на карточке, `DiadocPacketFlowService.acceptDocument`, экраны.

## Готово, когда

- Каждая причина из плана даёт отказ с этой причиной; несколько причин возвращаются вместе.
- Пакет без причин согласуется, в `PacketDocumentFlow` попадают только свои документы.
- Флаг Диадок, появившийся после наработки, учитывается при `/approve`.

## Как себя проверить

- IT на каждую причину отказа, на успешное согласование и на состав документов (связанный
  документ и СЧФ-дополнение не попадают).
- Тест ответа контроллера `/approve` с причинами.
- Весь набор `./gradlew :app:test` зелёный.
