## Сделано

- **Уровни нарушений.** `DiadocViolationLevel`: `NOT_APPLICABLE` / `VIOLATION` / `WARNING`
  (`warning`, «Предупреждение»), `ERROR` убран. Новый changeSet 10 в
  `tbl-diadoc_sign_settings_violation.xml` переводит `error` → `violation`, changeSet 11 обновляет
  remarks колонки; старые changeSet-ы не тронуты. `MirrorPacketViolationService.collectResults`

  `findCalculatedResult` — итог по самому тяжёлому: VIOLATION > WARNING > NORM. Экран настроек
  берёт `DiadocViolationLevel.values()` с подписями из messages — дескриптор и контроллер не менялись.
- **Таблица `packet_check`** и entity `PacketCheck` (`diadoc_PacketCheck`): колонки из плана,
  unique `UK_PACKET_CHECK_SOURCE` (`source_type`, `source_key`), jsonb через `JsonNodeB`, как
  `DiadocPacket.violations`. Источник — Jmix-enum `PacketCheckSourceType` (`DIADOC`).
- **API для t02–t05** (пакет `ru.fgk.ws.app.diadoc.check`):
  - `PacketCheckItem(source, code, severity, message, params, documentEntityId)` — позиция;
    фабрики `violation(...)`/`warning(...)`, `summaryStatus(items)`, константа `CHECK_FAILED`;
  - `PacketCheckSource` (`PROCESSING`/`BUSINESS`/`DIADOC`), `PacketCheckSeverity`
    (`VIOLATION`/`WARNING`, `toCode()` → `PackCheckedCodeEnum` для старых таблиц);
  - `AutoSignBlocker(code, message, params)` — причина запрета;
  - `PacketCheckJson` — перевод списков в jsonb и обратно.
  - В entity: `getItemList()` / `setItemList(list)` (ставит и `status`),
    `getAutoSignBlockerList()` / `setAutoSignBlockerList(list)`.
  - `PacketCheckService` (через `UnconstrainedDataManager`): `findDiadoc(messageId)`,
    `findDiadoc(Collection<UUID>)` → карта для списка пакетов одним запросом,
    `saveDiadocCheck(messageId, packetType, items)` — перезапись строки при наработке, `checked_at`
    = сейчас, `auto_sign_*` сбрасываются в null; `saveAutoSignDecision(check, items, blockers)` —
    для t04: позиции, `allowed = blockers.isEmpty()`, причины, `auto_sign_checked_at`.

- Messages: подписи `PacketCheck`, `PacketCheckSourceType`, `PacketCheckSource`,

## Решено без вас

- jsonb хранится как `JsonNode` (как `DiadocPacket.violations`), типизированный доступ — методы
  entity `getItemList`/`setItemList` и т.д.; `setItemList` сам пересчитывает `status`.
- Модель позиций — в новом пакете `ru.fgk.ws.app.diadoc.check`, сервис записи —
  `PacketCheckService`.
- `saveDiadocCheck` сбрасывает `auto_sign_*`: решение считалось по прежним позициям.
- Запись без upsert на уровне SQL: при одновременной наработке одного пакета вторая запись упадёт
  на уникальности — наработка одного пакета идёт последовательно.
- Колонка `status` — INT по `PackCheckedCodeEnum`, `source_type` — VARCHAR(50), `packet_type` —
  VARCHAR(255), без индекса сверх уникального.
