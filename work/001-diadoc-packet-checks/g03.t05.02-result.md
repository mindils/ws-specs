## Сделано

- **`PacketCheckDisplayService`** (`diadoc.service`) — результат проверки для экранов:
  - `correctPackets(packets)` — карта messageId → «Корректный пакет». Строки `packet_check` на все
    пакеты читаются одним запросом (`PacketCheckService.findDiadoc(Collection)`). Есть строка —
    «да», если `status` ≠ VIOLATION: предупреждения не мешают. Нет строки — итог флагов Диадок на
    лету (`MirrorPacketViolationService.findCalculatedResult`), правило то же. Флаги не рассчитаны —
    пакета в карте нет, ячейка пустая.
  - `findStatus(packet)` — итог для кнопки на карточке: строка, иначе флаги Диадок на лету.
  - `details(packet)` — содержимое окна: позиции и решение `AutoSignDecisionService.calculate`
    (без записи). Есть строка — позиции из решения: в них флаги Диадок пересчитаны. Нет строки —
    позиции `DIADOC` на лету, сбой даёт `PROCESSING`/`CHECK_FAILED` через
    `PacketCheckPipeline.runGuarded`. У СЧФ решения нет.
- **Список (`DiadocPacketListView`):** при смене коллекции `packetDocumentsDc` карта пересчитывается
  пачкой, рендерер колонки только читает карту. `displayedCorrectPacket` списком больше не
  вызывается.
- **Карточка (`DiadocPacketDetailView`):**
  - кнопка `showCheckResultButton`: текст — итог (Норма / Нарушение / Предупреждение), без итога —
    «Не проверен»; кнопка всегда активна, потому что окно показывает и автоподписание. Скрыта
    только у СЧФ без рассчитанных флагов. Тема: нарушение — `error`, норма — `success`,
    предупреждение — без темы;
  - окно «Результат проверки»: таблица позиций (источник, уровень, текст; уровень окрашен
    `--lumo-error-text-color` / `--lumo-warning-text-color`), «Замечаний нет», если позиций нет;
    ниже «Автоподписание: можно / нельзя» и список причин. Сбой расчёта — уведомление об ошибке.
  - Прежнее текстовое окно (`openTextDialog`) удалено: других вызовов не было.
- Messages: `diadoc.view.diadocpacket/checkResult.*` (10 ключей).

## Решено без вас

- Логика экранов — в отдельном сервисе `PacketCheckDisplayService`, а не во views.
- Решение об автоподписании на карточке считается от имени системы (`SystemAuthenticator`). Его
  проверки читают `PacketFlow` и `NvProcessingSettings` обычным `DataManager` (так в t04). Без прав
  на них пользователь увидел бы ложные причины, например «автосогласование не настроено». Решение
  только показывается и не сохраняется. Права ролям не добавлял.
- «Корректный пакет» без строки тоже считается как «нет нарушений»: только предупреждения дают
  «да», как и при строке. До t01 предупреждений у флагов Диадок не было, так что для СЧФ результат
  прежний.
- Кнопка у ненаработанного пакета (кроме СЧФ) видна с текстом «Не проверен»: окно объясняет, почему
  пакет нельзя автоподписать. Раньше кнопка без отметки скрывалась.
- Пакет без строки больше не берёт отметку из старых таблиц типа: по плану без строки — только
  флаги Диадок. `DiadocPacketCheckResultService.findCheckResult`/`displayedCorrectPacket` экраны
  пакета больше не вызывают. В основном коде вызовов не осталось, только в тестах (СЧФ, адаптер
  t03 сверяет с ними итог). Методы не удалял: это код другой группы. Удалить их можно в приёмке
  или отдельной правкой.
- У кнопки Lumo нет темы предупреждения, поэтому предупреждение — без цвета (раньше было `success`).
