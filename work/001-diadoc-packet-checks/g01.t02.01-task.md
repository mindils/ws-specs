## Коротко

Конвейер проверок пакета: шаги, состав по типам, запись строки `packet_check` при наработке,
`ok` ответа `processPacket` по новой строке. Флаги Диадок перестают попадать в старые таблицы.
Всё по разделам плана «Конвейер проверок» и «Правила результата»; модель позиций и entity — из t01.

## Что сделать

- Интерфейс шага, контекст, отчёт (позиции + итоговый статус), класс состава шагов по типам из
  `PacketParserService.dispatch`, исполнитель конвейера. Падение шага — позиция `CHECK_FAILED`.
- Шаги `PROCESSING` и `DIADOC` (логика и тексты `DIADOC` — из `MirrorPacketViolationService`,
  с уровнями из t01; код позиции = вид нарушения). Место под шаг `BUSINESS` (его делает t03) —
  состав должен принимать его без переделки.
- Запись строки `PacketCheck` целиком (upsert по `source_type` + `source_key`), `checked_at`.
- Дубль позиций новых бизнес-шагов (не адаптера) в старую таблицу через
  `DiadocPacketCheckResultService.appendResults`; механизм покрыть тестом с тестовым шагом.
- `PacketParserService.dispatchAndResolve`: конвейер после парсера и при непройденном разборе;
  `ok`/`errorType`/`message` из отчёта (`ok` только при NORM). Вызов
  `DiadocPacketViolationCheckService.applyTo` убрать; сам сервис удалить или сократить до того,
  что ещё понадобится t04 (проверка «в подписании» переезжает в решение об автоподписании).
- `MirrorPacketViolationService` остаётся для чтения на лету (СЧФ, пакеты без строки), но
  нарушения считает той же логикой, что шаг `DIADOC` — без двух копий.
- Другие вызывающие `PacketParserService` (`PacketReprocessService`, `DiadocManualSyncService`,
  `RefreshPacketTypeMenuProvider`, `PtRepairRestController`, `DiadocPacketDetailView`) должны
  работать как раньше — проверь по тестам.

Не трогать: парсеры, АСУ ВРК, экраны (t05), `PacketApprovalService` (t04).

## Готово, когда

- После наработки пакета любого типа из `dispatch` есть строка `packet_check` с позициями
  `DIADOC` (по настройкам) и, при сбое разбора, `PROCESSING`; при повторной наработке строка
  заменяется, старые позиции не остаются.
- Флаги Диадок не дописываются в старые таблицы типа.
- `processPacket` отдаёт `ok = true` только при NORM; текст `message` — тексты позиций.
- «Связанный документ в подписании» больше не нарушение.

## Как себя проверить

- Unit на шаги, состав и исполнитель (в т.ч. падение шага, дубль бизнес-шага в старую таблицу).
- `./gradlew :app:test --tests "ru.fgk.ws.app.it.DiadocViolationCheckReplayIT"` — переписать на
  новую таблицу; `PacketParserServiceTest`, `PacketParserRestControllerTest`,
  `DiadocManualSyncServiceTest`, `PtRepairRestControllerTest` — зелёные.
