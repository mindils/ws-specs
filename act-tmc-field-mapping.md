### 2.2. Строки (row) — детали из `pt_repair_packet_moving_mh`

Каждая строка — одна деталь (колесная пара, подшипник и т.д.) из акта перемещения.

| Поле XML | Откуда берём | Пример (КП) | Примечание |
|----------|-------------|-------------|------------|
| `name` | `nsi_nv_part_type.name` через `moving_mh.part_type_id` | `"КОЛЕСНАЯ ПАРА"` | Наименование детали, приводим к верхнему регистру. В БД хранится "Колесная пара", в XML пример "ПАРА КОЛЕСНАЯ" — **порядок слов может отличаться, сейчас просто uppercase** |
| `gost` | `pt_repair_packet_moving_mh.gost` (VARCHAR 4) | `"ЦКК ГОСТ"` | **Проблема**: в БД хранится только тип: `"ГОСТ"` или `"ТУ"` (4 символа). Для КП добавляем префикс `"ЦКК "`. Но в XML пример показывает полный номер: `"ЦКК ГОСТ 10791-2011"` или `"ЦКК ТУ-0943-157-01124328-2003"`. **Вопрос**: Откуда брать полный номер ГОСТа/ТУ? ## 3. Сводка нерешённых вопросов

### Критические (без них XML будет неполным)

| # | Поле | Вопрос |
|---|------|--------|
| 1 | `sender_org` / `owner` | Откуда брать полное наименование ФГК с адресом? Это константа ("АО ФГК, Екатеринбург, Куйбышева 44А...") или берётся из какого-то справочника? Если константа — одна на все акты? |
| 2 | `sender_filial` | Откуда брать наименование филиала ФГК (АТО)? Пример: "Челябинское АТО ФГК". Привязано к депо ремонта? К договору? Есть справочник соответствия депо → АТО? |
| 3 | `recipient_org` | Откуда брать полное наименование организации-получателя? Это всегда структура РЖД (ЦДИ)? Привязано к дороге? |
| 4 | `recipient_filial` | Откуда брать структурное подразделение получателя? Привязано к дороге / региону? |
| 5 | `condition` / `code_pr_mat` | Состояние детали и код приёмки — нет в таблице `pt_repair_packet_moving_mh`. Нужно ли добавить эти поля? Или для перемещения всегда одно значение ("Отремонтированная" / код 2)? |
| 6 | `code` | Код материала (напр. "3183810088") — откуда его брать? Привязан к типу детали? Нужен справочник? |

### Важные (влияют на полноту данных)

| # | Поле | Вопрос |
|---|------|--------|
| 7 | `gost` | Полный номер ГОСТ/ТУ (напр. "ГОСТ 10791-2011"). В БД хранится только "ГОСТ" или "ТУ". Для КП это всегда один и тот же ГОСТ? Или нужен справочник? |
| 8 | `srok` | Вторая часть после `/` (напр. "64-60**/939-930**"). Что это? Диаметр колеса? По какой формуле считается? |
| 9 | `rim` | Фактическая толщина обода (напр. "62,0; 62,0"). В БД не хранится. Откуда её брать? Из данных осмотра? |
| 10 | `storage_tor` | Код участка ТОР (ID РМ). Какой справочник? Как привязан к депо? |

## 4. Схема источников данных

```
pt_repair_packet_moving          pt_repair_packet
├── act_number     → doc_num     ├── inn           → inn
├── act_date       → doc_date    ├── kpp           → kpp
├── moving_depo_id               ├── contract_number → contract_num, dognum
├── message_id ──────────────────┤  contract_date  → contract_date, datedog
│                                ├── depo_id ──→ nsi_v_depo
│                                │                  ├── depo       → kleimo, storage_kleimo
│                                │                  ├── short_name → depo, storage
│                                │                  └── rw_id ──→ nsi_v_railway
│                                │                                  └── rw_name → dor
│                                │
pt_repair_packet_moving_mh       │
├── part_type_id ──→ nsi_nv_part_type
│                      ├── name  → row.name (uppercase)
│                      └── mnem  → для определения КП-специфичных полей
├── detail_number  → serial_num, serial_num1/2/3 (парсинг по "-")
├── gost           → row.gost (+ префикс "ЦКК " для КП)
├── ws_rim_id ──→ nsi_v_nv_ws_rim
│                  ├── rim_max  ─┐
│                  └── rim_min  ─┴→ row.srok ("max-min")
├── axle_type_id ──→ nsi_v_nv_axle_type
│                      └── type → row.name3 (без дефиса, только КП)
├── quantity       → row.quant
├── price          → row.price
└── price_total    → row.cost (формат .0000)
```
