## Как пользоваться пакетом

1. Брать функциональную задачу F02–F08; в приложении проверять только M001–M003 и N002. Карточки содержат источники и зависимости; общий checklist приёмки — F11.
2. Скилы Jmix применять при реализации. Код/псевдосинтаксис в спецификации не заменяет проверку API разрешённой версии Jmix/Vaadin.
3. Отмечать результаты в PR/task tracker и ссылаться на ID. Пакет описывает исходный снимок; повторная генерация F09/F10 обновляет снимок, но не должна возвращать отложенные страницы в текущий объём.
4. Для обновления снимка выполнить `python3 specs/rvk-filter-production-rollout/build-inventory.py`; результаты — [page-inventory.json](page-inventory.json), F09/F10. Скрипт пишет только в эту папку.

В данном checkout `specs` исключён из основного Git (`.git/info/exclude`), вложенного `specs/.git` нет — как и `openspec/.git`. Файлы созданы на диске; Git-репозиторий и настройки исключения не менялись. Поэтому команда вида `git -C specs commit` из AGENTS.md/CLAUDE.md выполняется **в основном репозитории** (Git поднимается к ближайшему `.git`): `add -A` там ничего не добавит из-за exclude, а `commit` заберёт то, что уже в индексе основного проекта. Для переноса/версионирования пакета потребуется принятый в вашей среде отдельный репозиторий specs либо копирование папки; обычный commit основного проекта эти файлы не включит.
