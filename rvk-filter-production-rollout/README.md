# RVK Filter: подготовка к production и перевод страниц

**Статус пакета:** аудит и спецификации подготовлены 2026-09-05. Доработки аддона и перевод страниц не начаты.

Цель — универсальный аддон Jmix 3.0.x / Java 21 / PostgreSQL с удобной панелью, личными и общими пресетами, безопасным обслуживанием настроек и постепенным внедрением в rvk-ws. Изменения аддона выполняются в соседнем rvk-filter; доменные запросы и адаптеры остаются в rvk-ws.

Проверка обнаружила **79 страниц со стандартными фильтрами и 16 с собственным поиском/параметрами**. Очередь перевода — **95 страниц**, очередь добавления — **45**, явных исключений — **61**. Полный реестр содержит пути, загрузчики, операции, JPQL, поля, source-роли, Java-обработчики и зависимости каждой страницы.

## Что уже проверено

- Аддон `54bf5d7`, приложение `9b0a52b3b`: production imports не зависят от приложений-потребителей.
- `clean test :rvk-filter:jar`: **224 прошедших теста, 2 skipped** (уникальность PostgreSQL). 7 JS прошли syntax check; ресурсы упакованы в JAR.
- XML well-formed; самостоятельная XSD-валидация выявила отсутствие import layout namespace. Это не доказательство отказа Jmix loader.
- В локальной PostgreSQL нет rvk_filter_config, старая flowui_filter_configuration существует и пуста. Production не проверялся.
- IDE-инспекция целевого проекта и браузерное отображение аддона в app не подтверждены.

Основные блокеры: Reset/state не соответствует запросу; UI не обновляет существующие presets и неверно вызывает общий default; не хватает защиты прямых записей, контроля версий и конкурентных изменений. Для широкого перевода нужны entity pickers, typed JPQL/IN, операции и AND/OR. Подробные доказательства — [F01](01-audit.md).

## Решения пользователя

| Вопрос | Принято |
|---|---|
| Первая production-платформа | Любое приложение Jmix 3.0.x, PostgreSQL; другие СУБД отдельным этапом |
| Общие пресеты | Видны пользователям доступной страницы; управление по rvkfilter.manageGlobal |
| Личные пресеты | Пользователь управляет своими; обслуживание чужих только по отдельному manageAllConfigs |
| Обслуживание | Универсальный admin экран и SQL-инструкция |
| Выбор preset | Заполняет поля; данные изменяются по «Найти» |
| Reset | Восстанавливает и применяет исходные XML/Java условия страницы |
| Старые фильтры | Сохранить, поместить в закрытую гармошку; активировать явным переключателем |
| Старые сохранённые generic configurations | Оставить в старом режиме, автоматически не переносить |
| Пилот | Типы деталей → причины отклонения → депо |
| Охват | Существующая фильтрация, затем все подходящие списки |

## Очередь внедрения

| Волна | Очередь | Количество |

| 3 | M017–M025: справочники со сложной фильтрацией | 9 |
| 4 | M026–M034: договоры, уведомления, претензии | 9 |
| 5 | M035–M044: вагоны и архивы ремонтов | 10 |
| 6 | M045–M055: документооборот, контроль, выгрузки DR/DT | 11 |
| 7 | M056–M080: пакеты, delegates и специальные контексты | 25 |
| 8а | M081–M095: существующие нестандартные фильтры/отчёты | 15 |
| 8б | N001–N045: дополнительные списки | 45 |

Сначала основная волна, затем следующая; внутри волны — порядок карточек по viewId. Простая страница может идти раньше своего доменного семейства; delegates/специальные контексты идут позже. Реестр определяет конкретный порядок, названия волн объясняют его. При переводе проверять права, первый запрос/default, эквивалентность ID/count/export и возврат в старый режим.

Для дополнительных страниц каталог начинается с property-колонок указанного основного грида, разрешённых текущему пользователю и поддержанных источником. Дочерние гриды и composition не подключаются автоматически. Вычисляемое поле нуждается в явном provider, а не фиктивном JPQL к DTO.

## Как пользоваться пакетом

1. Брать функциональную задачу F02–F08, затем соответствующую страницу M/N. Карточки содержат источники и зависимости; общий checklist приёмки — F11.
2. Скилы Jmix применять при реализации. Код/псевдосинтаксис в спецификации не заменяет проверку API разрешённой версии Jmix/Vaadin.
3. Отмечать результаты в PR/task tracker и ссылаться на ID. Пакет описывает исходный снимок; повторная генерация F09/F10 сбрасывает их статусы к начальным.
4. Для обновления снимка выполнить `python3 specs/rvk-filter-production-rollout/build-inventory.py`; результаты — [page-inventory.json](page-inventory.json), F09/F10. Скрипт пишет только в эту папку.

В данном checkout `specs` исключён из основного Git, вложенного `specs/.git` нет. Файлы созданы на диске; Git-репозиторий и настройки исключения не менялись. Для переноса/версионирования пакета потребуется принятый в вашей среде отдельный репозиторий specs либо копирование папки; обычный commit основного проекта эти файлы не включит.
