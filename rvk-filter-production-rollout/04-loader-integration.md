# F04. Применение фильтра и интеграция загрузчиков

[К плану](README.md) · Общий механизм: `rvk-filter`; адаптеры: `rvk-ws` · Статус: **в работе** — F04.1 и часть F04.2 реализованы для CollectionLoader; [результаты](12-implementation-log.md).

## F04.1. Единая семантика состояния — до пилота

Разделить четыре состояния: серверная конфигурация полей; исходные значения страницы; редактируемый draft; успешно applied. Выбранный preset — источник draft, а не свидетельство, что таблица уже отфильтрована.

| Действие | Поля | Загрузчик/данные |
|---|---|---|
| Первое открытие | Личный default, иначе общий, иначе XML/Java default страницы | Применить выбранное состояние до **первой** загрузки |
| Выбор пресета | Заменить draft, пометить «Есть неприменённые изменения» | Не загружать до «Найти» |
| Найти / Enter | Валидировать snapshot draft | Применить, первая страница, одна загрузка; только после успеха обновить applied |
| Сбросить | Вернуть XML/Java default, снять selected preset | Применить этот default с базовыми ограничениями, одна загрузка |
| Ошибка конвертации | Оставить draft для исправления, показать поле ошибки | Сохранить прежние applied/данные/пагинацию |
| Ошибка запроса/provider | Сохранить draft, показать ошибку | Откатить вклад/пагинацию к прежнему applied; не показывать успех |
| Повреждённый стартовый preset | Показать проблему и действие выбора другого/сброса | Не грузить автоматически расширенную выборку; после явного сброса применить безопасный page default |

Первоначальное применение defaults реализовано и проверено; прежнее поведение «XML default только заготовка» больше не актуально. Контракт описан в release notes и подтверждён lifecycle-тестами. Вызовы в Init/BeforeShow/Ready/Attach приложения согласовать: никаких первоначальных запросов до установки требуемых условий.

## F04.2. Владение условиями

- [x] Выделить API построения Condition без загрузки, применения, приостановки/возобновления интеграции и обновления базового контекста. Не использовать повторный `setDataLoader()` как способ захватить уже смешанные условия.
- [x] Базовые ограничения (родитель, выбранный пакет/период, обязательный тип документа, permissions) задаёт host; пользовательский фильтр добавляется через AND. Пресет не может их удалить.
- [x] Отслеживать вклад активного механизма отдельно от baseCondition. Переключение F08 снимает только старый пользовательский вклад, не весь query, security constraints и обязательные параметры.
- [x] Обновление host baseCondition через setBaseCondition пересобирает вклад из applied, сохраняя draft. Подтверждено PostgreSQL-тестом suspendResumeAndHostChangesUseAppliedState.
- [ ] Замена родителя/контекстных параметров в доменном delegate использует актуальный baseCondition; требуется при реализации соответствующего адаптера, а не добавление фильтра на отложенную страницу.
- [ ] Обновление данных, count, simplePagination, сортировка и «выгрузить всё» используют один applied snapshot. Draft не должен попадать в экспорт до Apply.
- [ ] Detach/attach не удваивает listeners; повторное открытие освежает список пресетов. Два фильтра/экземпляра фрагмента на одном view изолированы по ключу и параметрам.

## F04.3. Адаптеры

| Путь | Реализация | Признак приёмки |
|---|---|---|
| CollectionLoader с JPQL | Штатное дерево Condition | Равенство ID/count, один запрос загрузки, корректная страница |
| Repository delegate с JmixDataRepositoryContext | Сохранить штатную передачу context в repository; не потерять обязательный предикат repository method | Пример DR packet: тип пакета остаётся ограничен даже после Reset |
| LoadContext delegate | Убедиться, что delegate использует query.condition; иначе адаптер переводит state в собственные параметры | Тест не только вызова load(), но и реально изменившегося результата |
| PreLoad-обогащение | Отделить доменные условия от старых UI-значений; активный режим предоставляет значения адаптеру | Неактивные поля не влияют на Query |
| REST DataStore | Передавать поддерживаемые Property/LogicalCondition; unsupported operation/type отклонять до загрузки | Не ограничиваться warning в RestFilterBuilder, не игнорировать JPQL |
| DTO/SQL function/report | Адаптер state → типизированные параметры сервиса/repository. Для ограниченного полного in-memory набора — явный серверный predicate adapter | Нет фиктивного `setCondition`, который delegate игнорирует; суммы/группы и экспорт совпадают |
| TreeDataGrid | Фильтровать по правилам источника с сохранением необходимых предков; отчётные параметры и визуальные переключатели различать | Нет потерянных дочерних строк/сумм; дерево остаётся навигируемым |
| Property-bound composition | Не создавать query loader ради фильтра | Такие редакторы исключены из F10; отдельная будущая задача при явной необходимости |

Один адаптер на поведение источника, а не отдельный универсальный переключатель, пытающийся переписать произвольный Java-код через reflection. Общие интерфейсы находятся в аддоне; знания о договорах, вагонах, пакетах и функциях — в приложении.

## F04.4. Конкретные сложные пути — backlog приложения

Все страницы ниже исключены из текущего внедрения. Адаптацию их контроллеров сейчас не выполнять. Универсальные контракты аддона остаются отдельными функциональными задачами.

- `diadoc_DiadocPacket.list`: `entityIdField`, `torIdField`, contractor ИНН/КПП и depot picker; см. [контроллер](../../app/src/main/java/ru/fgk/ws/app/diadoc/view/diadocpacket/DiadocPacketListView.java). Пустой результат resolvePacketIds должен оставлять пустую таблицу.
- `PtRepairPacket.list`: PreLoad и динамический `diadocStatusFilter.setCondition`; все ветви привязать к режиму.
- `rp_VRpOperBalance.list`: AbstractParams.createFromFields и функция отчёта; нельзя заменить только XML. Колонки «показывать загрузку/среднее время» — настройки представления, не условия выборки.
- `pt_1cBalance.list`: смена базового query по storage cell; текущая ячейка остаётся обязательным контекстом.
- `wn_VWagOperArchive`: карточка вагона с фильтром дат; обязательный id вагона не хранится в пользовательском пресете.

## Приёмка

До пилота: apply/reset/default, повреждённое состояние, два режима, первая загрузка, пагинация, роль обычного пользователя. Перед сложной волной: отдельный интеграционный тест соответствующего delegate/REST/provider, сравнение count/ID/export и ручной browser-проход. Не считать runtime-путь проверенным по одной компиляции.
