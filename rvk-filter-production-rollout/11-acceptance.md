Для browser-прохода использовать уже запущенный пользователем экземпляр либо собственный фоновый процесс; дождаться `/actuator/health=UP`, после проверки остановить только свой процесс. Если браузерный путь недоступен, выполнить подходящий UI integration test и явно указать `render not browser-verified` — не объявлять визуальную часть завершённой.

## Матрица регрессий аддона

| Сценарий | Ожидаемый результат |
|---|---|
| Найти после редактирования / выбора пресета | Один запрос; applied и chips соответствуют данным |
| Reset с непустыми XML/Java defaults | Применены исходные значения, сохранён base context |
| Первый показ с личным/общим default | Верный приоритет, нет первоначальной широкой загрузки |
| Некорректная дата/число/UUID/диапазон | Сообщение у поля, прежние applied/данные сохранены |
| BOOLEAN false, numeric 0, IS_SET(false) | Значимые значения не теряются |
| Повторный JPQL `?`, Date, enum, IN, JOIN | Типы корректны, параметры не конфликтуют, count не раздут |
| Две группы OR/AND и повтор одного поля | Сохранение/чтение воспроизводит исходное дерево |
| V1 preset / неизвестная версия / удалённое поле | V1 мигрируется без потерь; несовместимые не применяются молча |
| Обновление preset / rename / copy / delete | Предсказуемые UUID/version/scope и сообщения |
| Снятие роли после открытия панели | Серверное изменение запрещено несмотря на старые кнопки |
| Большие options и много presets | Пагинация/поиск, без полной загрузки большого справочника |
| Два компонента и повторный attach | Изолированные ключи/параметры, нет дублирующихся listeners |
| Старый/новый mode, конфликтующие условия | Действует ровно выбранный режим; base/security сохранены |
| REST/delegate, который не умеет Condition | Явный adapter либо понятный отказ, не фильтр-пустышка |

## Приёмка действующих страниц; шаблон для будущего backlog

Сейчас для M001–M003 и N002; для остальных карточек только после возвращения из backlog. Оформить отдельную задачу/PR с её task ID; общий scope страницы не расширять соседними legacy-refactors.

1. Зафиксировать исходный query, обязательные параметры/parent context, defaults, роли, URL/settings и все пользовательские handlers из реестра. Значения renderer и настройки колонок не переносить в условия.
2. На изолированном наборе данных получить ID/count/sort старого режима: пустой фильтр, каждое условие, комбинация, null/false/0, граничные даты, пустой результат. Для generic — каталог и AND/OR; для отчёта — также суммы/группы.
3. Повторить в новом режиме; проверить каждое значение из списка, lifecycle первой загрузки и Reset. Сравнивать данные при одинаковом контексте и сортировке, а не только скриншоты.
4. Проверить pagination/page-size, refresh, count, Excel/«выгрузить всё», выбор строки и переход в detail. Экспорт не должен использовать неприменённый draft.
5. Под A/B проверить личные пресеты, под manager общий CRUD/default; прежние generic configurations доступны в старом режиме. Для N-страницы исходным состоянием служит список без нового фильтра.
6. Переключить режимы не менее двух раз, в том числе с противоречащими условиями. Программное восстановление старых полей/URL не меняет новый запрос. Изменение родителя сохраняет обязательные ограничения.
7. Выключить серверный feature flag страницы и проверить возврат к прежнему поведению без пересборки frontend. Для N-страницы проверить исходный список.
8. Зафиксировать пофайловый Gate 1, результат :app:test и отдельный browser verdict по view/кнопкам/полям. Только после этого отметить карточку выполненной.
